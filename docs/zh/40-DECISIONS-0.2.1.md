### 0.2 术语表

本节给每个术语**判定边界**，不是同义词循环。下游五份文档遇到这些词，一律按本节的边界用。

**自动补绑**
：核在**运行期**按周期把「影响范围（3×3 区块）内、区块已加载、未被任何核收录」的培养器补进自己 16 条绑定列表的**写入动作**。判定边界：补绑是**新增一条绑定**（`addCultivator`），不是「改绑」、不是「就近漂移」、不是「重新选核」；它**只补未绑定的**，不摘、不改、不搬任何已绑条目；它**不强制加载区块**（裁定 #2）；它**不改变** 0.2.0 的选核判据（最近 + 己方 + 未满，`OutpostCoreBlockEntity:276-317`）。补绑是绑定的**第三个写入时点**，前两个是培养器放置（`CultivatorBlock:86-102`）与拆核迁移改绑（`OutpostCoreBlockEntity:685-691`）。它按裁定 #12 **部分取代** D-165 补充里「运行期不做「就近漂移 / 定期重绑」」与「不要在运行期偷偷补绑」两句（D-165 的其余部分全部保留，见 §5）。

**未绑定**
：一个培养器**没有**被任何核的 16 条列表收录的状态。判定边界：唯一真相在**核侧**列表（0.2.0 的 D-165）；培养器 BE 里那份「我绑给谁」是**引用缓存**，可用性判定要用核侧 `hasCultivator` 校验（`CultivatorBlockEntity:116-125`）。「未绑定」**不等于**「被拆掉」、**不等于**「不可见」、**不等于**「任何核都能抢」——它只是补绑的**候选**，仍须过「覆盖 + 己方 + 有空位」三道判据；补绑写入时**两侧都要写**（核侧 `addCultivator` + 培养器侧 `setCore`）。

**mount 模式**
：Q弹 的两种表现分支之一，由**服务端** config `qbounce.poseMode` 选中；处于该分支时，带 Q弹 的实体会被挂一个隐形 `ArmorStand` 坐骑（`QbounceMountController:242-272`）。判定边界：mount 是**全局配置分支**，不是某个实体的属性、不是玩家输入、不是客户端状态；另一分支 `render` **不是** mount。删 AI 必须跳过 mount（裁定 #7），因此「当前是否 mount」只能问 `QbounceMountController`，**不得**在效果类里另解析一遍配置（否则同一件事有两份真相）。

**删 AI**
：对 `Mob` 调 `Mob#setNoAi(true)`，使原版 AI 的目标选择与移动停止。判定边界：删 AI **不是**「让生物停止移动」的泛称（`BRIEF` §6 硬禁令第 4 条）——它不改伤害、血量、掉落、碰撞、被击退、被推动，也不改 `isNoAi` 之外的状态；**有恢复语义**（见「原值」，裁定 #8）；对象是 **`Mob`**，不是 `LivingEntity`（现成谓词形态 `WildHunterAura:88`）；玩家**恒不在**对象内（玩家不是 `Mob`）。

**原值**
：一个 `Mob` **在被删 AI 之前**的 `isNoAi()` 读数（`true` / `false`）。判定边界：恢复写的是**这个读数**，不是常量 `false`（裁定 #8）；原值**记在实体上**（NeoForge 实体附件，**跨读档成立**，裁定 #15），**用完必须及时删除**、不许留残留；附件里**不存任何时间戳**——到期刻只在内存（裁定 #16）；「进入前本来就是 `noAi`」的实体离开时**仍应是 `noAi`**，不得被本版「顺手恢复成有 AI」。现成先例 `WildHunterAura` 的 `AI_RESTORE_AT`（`:52`）**不合**本定义：它存「到期时刻」、恢复写死 `setNoAi(false)`（`:119`），这正是裁定 #8 要改掉的口径。

**敌对生物**
：满足「`net.minecraft.world.entity.monster.Enemy` 实例」**或**「`MobCategory.MONSTER`」的 `LivingEntity`（并集，裁定 #9）。判定边界：这是**本版新增**的判据（全仓 `Enemy` / `MobCategory.MONSTER` / `isHostile` 命中均 0，`BRIEF` §1.5）；它**宽于**既有 5 处 `Monster` 过滤，因此**只用于 ×3 的那一道闸**，不回改触发面；玩家**恒不是**敌对生物；「非玩家生物」与「敌对生物」**不是同义词**（震动豆的对象是前者，×3 的对象是后者）。

**倍率**
：`trap.damageMultiplier`——`trap` 组里新增的 1 个**全局** config 键（类型 double，默认 **3.0**）。判定边界：倍率**不是**改各作物默认值（`blast_carrot.maxDamage` 7、`zangief_cane.slamDamage` 7.5 一个都不动）；**不是**在伤害事件层统一乘（§6 第 2 条）；**不是**「所有陷阱都参与」——4 个 `TRAP` 作物里只有 **2 个**真的参与（裁定 #11，见 D-184）；它乘的是**最终伤害**，不是威力、不是封顶值、不是爆炸半径；它只对**敌对生物**生效，对玩家与非敌对生物无效。

### 0.3 四字段写法

每条决策固定四项，**缺一不可**，顺序固定：

| 字段 | 写什么 | 不许写什么 |
|---|---|---|
| **结论** | 一句话、祈使句、可直接执行 | 条件句、备选句、「可以考虑」 |
| **依据** | `BRIEF` §2 的裁定编号，或 §1 / §3 / 源码的 `文件:行号`；两者都给最好 | 「因为合理」「符合直觉」「业界惯例」 |
| **落地位置** | 要改的 `路径` 或 `类#方法` | 代码片段、算法步骤 |
| **补充** | 这一条**连带会影响什么**、**否决掉了哪些替代方案** | 实现细节（那是 42 号的事）、任务排期（那是 43 号的事） |

五条写作纪律：

1. **「本文补充」标记**：凡由本文推导、而非 `BRIEF` 直接给出的口径，在该句前标 **本文补充**。带这个标记的条目可以被作者否决；不带标记的是 `BRIEF` / plan 的转写，否决它等于否决作者裁定。
2. **数字纪律**：本文所有数值只能追到 `BRIEF` §0 / §1 / §2 / §3 的某一条，或两个已给数值的算术（如 175 + 1 = 176、337 + 1 = 338、97 + 0 = 97、`LCM(40, 100) = 200`）。**需要新数值的**写成「由 41 / 42 号在本条框架内定」，本文不自己编。
3. **禁用词**：不出现未定事项与待办标记；不用第二人称敬语，一律用「作者」。
4. **与源码的关系**：本文与源码冲突时报给作者，不自行取舍，也**不改** `BRIEF`。
5. **只写决策**：不写实现步骤、不写任务拆解、不写排期、不写验收细则——它们分别是 42 / 43 号的事；本文只给「定为 X」与「为什么是 X」。

| 8 | **把「AI 原值」存成到期时刻**（照 `WildHunterAura:52` 的现成形态，落盘到期时间） | ① 到期刻是运行期状态，一旦落盘就要处理「读档后已过期 / 停服期间时间流逝 / 系统时钟」三类边界，而原值只需要一个布尔；② 本版震动豆的 80 刻窗口**不跨档**（裁定 #16），到期刻根本不需要落盘；③ 落盘的东西越少越不容易腐烂——附件只留原值 + 引用计数，读回来即可用 | 作者，v0.2.1 访谈（裁定 #16 定为「不跨档」，并明确否决「存到期时刻」） |

八条墓碑的读法：**第 1、2、5 条是「不改什么」**（尖牙、事件层、区块加载），**第 3 条是「不合并」**（两条扫描），**第 4、6、7 条是「语义收窄」**（恢复原值、mount 跳过、范围而非单体），**第 8 条是「不落盘期限」**（原值可以落盘、到期刻不行）。下游若在某处想「顺手」做这八件事中的任何一件，先回本文找到对应的否决理由。
