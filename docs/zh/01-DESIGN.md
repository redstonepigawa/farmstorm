## 0. 阅读约定

1. **数值来源**：本文所有玩法数值照抄 §plan.txt§，不做任何平衡调整（D-21）。凡 §plan.txt§ 未给出的实现必需参数，统一登记在 §3.8.6「数值补全登记」，并标注编号。凡 §plan.txt§ 表述与决策冲突的，以 §00-DECISIONS.md§ 为准（见附录 A 修正条目 C-1~C-5）。
2. **标注法**：§[D-xx]§ 表示该结论直接来自决策记录；§[C-x]§ 表示该结论来自对 §plan.txt§ 原文的修正；§[G-x]§ 表示该数值为补全项。
3. **单位**：时间一律用「秒」或「游戏刻（tick）」标注，1 秒 = 20 游戏刻。等级一律写「等级 N」，落库时 `amplifier = N − 1`。
4. **服务端权威**：所有判定、结算、状态迁移都发生在服务端。客户端只负责渲染、粒子和输入转发（D-23）。

## 1. 模组定位与设计目标

### 1.1 一句话定位

农场风云把 Minecraft 的**农产品**重新武装成**PvP 道具**：同一种作物既可以种在地里，也可以被扔出去、被架在墙上、被吃掉，从而把「种田发育」这条原有的和平路线，变成一条能直接参与战斗的装备路线。

### 1.2 设计目标

| 编号 | 目标 | 落地手段 |
|---|---|---|
| G1 | 让农业产出具备 PvP 价值 | 15 种改良作物全部至少挂载一个战斗向类别（伤害类 / 破障类 / 陷阱类 / 炮台类 / buff类） |
| G2 | 保留「种田」这条原有的成长曲线 | 每个作物都有播种形态，收获按原版比例同时掉作物与种子，闭环自给（D-08） |
| G3 | 让玩家一眼分清原版与改良 | 「农产品转换器」工作方块 + 材质右下角绿色「+」角标（§plan.txt§ 第 6、8 行） |
| G4 | 让改良作物「不再是原版作物」 | 改良作物不继承原版用途：不能做面包、不能喂动物、不参与原版配方（D-09） |
| G5 | 队伍维度可读、可扩展 | 己方判定走 `TeamResolver` 抽象接口，v0.0.1 用计分板队伍实现（D-06） |
| G6 | 服主可调 | 全部关键数值进 NeoForge 服务端 config（D-22） |

### 1.3 「原版作物 / 改良作物」的分界手段

分界必须**同时**由两个互相独立的手段表达，缺一不可：

**（一）玩法层：农产品转换器**

- 唯一的获取途径是转换器，而不是合成台。玩家拿到改良作物的第一步必然是「造一台转换器 → 喂原版作物 → 拿改良作物」。
- 转换器**双向 1:1，可逆**（D-11）。这意味着改良作物不是一条单向死路，玩家随时可以把用不上的改良作物变回原版作物止损。
- 转换器有**经验成本**（每次 3 点经验值，D-12），所以「批量转产」是有代价的行为，而不是零成本复制。

**（二）视觉层：材质右下角绿色「+」**

- 每一种改良作物的物品材质在**右下角**叠加一个**绿色**的「+」角标（§plan.txt§ 第 8 行）。
- 角标由资源包提供，尺寸与透明度由材质脚本统一生成，作者审校最终像素（D-25）。
- 角标**只加在物品材质上**；方块形态（部署方块、作物方块）的贴图沿用作物本体该有的外观，不叠加角标——玩家在野外看到一株作物时，看到的是作物，不是标签。
- 播种物品同样带角标，保证「这是改良种子」在物品栏里可读。

### 1.4 v0.0.1 的非目标

1. 不做数值平衡（D-21）。
2. 不做农夫乐事兼容（延后项 1）。
3. 不做 FTB Teams 接入，只留接口（延后项 2）。
4. 不新增「种植型」作物设计，只留接口与规范（D-10、延后项 3）。
5. 不加自定义指令（D-24、延后项 5）。

## 2. 词表与分类体系

### 2.1 术语表

| 术语 | 定义 |
|---|---|
| 原版作物 | §plan.txt§ 中 15 个条目「对应原版作物」一栏所指的 Minecraft 原版物品/方块 |
| 改良作物 | 本模组新增的 15 种物品，与 15 个原版作物一一对应 |
| 播种物品 | 改良作物的播种形态。有的是独立物品（如 `farmstorm:puffed_wheat_seeds`），有的是作物自身（如 `farmstorm:blast_carrot`） |
| 作物方块 | 改良作物种下之后长成的地块方块（`CropBlock` 同构） |
| 农产品转换器 | 唯一能把原版作物 ⇄ 改良作物互转的工作方块 |
| 转换配方 | 数据驱动的自定义 `RecipeType`，一行 = 一条「原版 ⇄ 改良」映射 |
| 部署方块 | 部署型作物放置后形成的方块实体（`Block` + `BlockEntity`） |
| 部署点 | 部署方块所在方块坐标（`BlockPos`），是多数距离判定的原点 |
| 依附方块 | 部署方块所贴合的那个方块，由「附着位置」决定 |
| 附着位置 | 部署方块相对于依附方块的方位：顶部 / 底部 / 侧面 |
| 悬空 | 依附方块消失后，部署方块是否仍然保留并继续运行 |
| 归属者（Owner） | 部署该方块的玩家，按 UUID 记录 |
| 己方 | 与归属者满足 `TeamResolver.isFriendly` 的玩家集合（含归属者本人） |
| 非己方 | 己方的补集 |
| 一次性部署物 | 触发即结算并自毁、不掉落的部署方块 |
| 持续部署物 | 部署后长期存在，按周期执行行为的部署方块 |
| 光环（Aura） | 持续部署物周期性对区域内己方玩家施加的一组效果 |
| 落点 | 投掷物终结位置的方块坐标与精确坐标 |
| 硬挖 | 破坏耗时被固定、不受工具与附魔影响的挖掘方式；v0.0.1 仅 `pumpkin_turret` 适用（D-13、D-37） |

### 2.2 维度一：类型（Type）

类型回答「**这个物品怎么被使用**」。类型是一个**单值枚举**——一个物品恰好属于一个类型。

#### 2.2.1 投掷型

- **正式定义**：可被玩家以右键投掷、产生一个独立投掷物实体、并在落点结算一次效果的物品。
- **行为契约**：
  1. 堆叠上限 **16**（D-16）。
  2. 每次投掷消耗 **1 个**；创造模式不消耗（D-16）。
  3. 投掷物初速度与重力沿用原版雪球类投掷物参数（补全 G-6 只补充寿命，不改运动）。
  4. 落点结算是**幂等**的：一个投掷物实体一辈子只结算一次。
  5. 结算必须发生在服务端主线程；客户端只播粒子与音效。
  6. 投掷型物品**不可食用**，即使对应的原版作物可以吃（D-09）。
- **生命周期**：
  `右键投掷 → 物品数量 −1 → 投掷物实体生成并飞行 → 命中方块 / 命中实体 / 超时（100 刻，G-6）/ 落入未加载区块 → 落点结算一次 → 实体 discard()`

#### 2.2.2 部署型

- **正式定义**：可被玩家右键一个方块的某个面、从而在该面相邻位置生成一个部署方块的物品。部署方块携带归属信息与运行状态。
- **行为契约**：
  1. 附着位置分三种：**顶部**（贴依附方块上表面）、**底部**（贴下表面）、**侧面**（贴四个水平面）。每种作物声明自己支持哪几种。
  2. 依附方块必须是**完整不透明方块**（判定见 §3.3.2）。
  3. 部署方块必须记录归属者 UUID。
  4. 部署方块的破坏规则**逐方块**决定：**只有 `pumpkin_turret` 固定硬挖 10 秒**（D-13、D-37）；其余部署方块（含 `awakened_torchflower` / `awakened_pitcher_plant`）己方挖掘按**原版正常速度**（D-14、C-8）。火把花与瓶子草额外「非己方玩家挖不动 + 任何爆炸无法破坏」（D-14）。
  5. 依附方块消失后是否保留，由条目声明的「悬空」决定，默认**不悬空**（掉落为物品本体）。
  6. 一次性 / 持续由条目指定，不按类型统一。
- **生命周期**：
  `手持右键方块表面 → 校验附着位置与依附方块 → 数量 −1 → 生成部署方块 + BlockEntity（写 ownerUuid / supportPos / supportFace）→ 进入 tick 循环 → 触发结算或周期性执行 → 被破坏（按破坏规则掉落）/ 一次性自毁（不掉落）`

#### 2.2.3 种植型

- **正式定义**：以作物方块形式生长、物品作为播种物、只能种在泥土 / 草方块 / 耕地上的类型。
- **v0.0.1 范围**：**不新增设计**，只保留接口与规范（D-10）。由于 15 个作物全部配有播种形态（D-08），全部天然具备种植能力，因此「种植型」在 v0.0.1 表现为一个**横切能力**而不是独立物品。
- **行为契约**：
  1. 播种物只能放在泥土、草方块、耕地（及其泥类变体）上；其他方块上拒绝并给出失败反馈。
  2. 成熟后破坏掉落：**同时掉落作物与播种物**，比例沿用原版对应作物的掉落表结构（D-08）。
  3. 骨粉加速、耕地干湿、光照要求等生长语义沿用原版作物方块。
  4. 改良作物方块**不参与原版配方**（D-09）。
- **生命周期**：
  `播种物右键方块 → 生成作物方块（age=0）→ 随机刻生长 → 成熟（age=max）→ 破坏 → 掉落作物 + 播种物 → 回到播种物`

#### 2.2.4 食用型

- **正式定义**：手持右键可进入食用动作、食用完成后施加一组效果的物品。
- **行为契约**：
  1. 食用时长 32 刻（D-29）。
  2. 效果在 `finishUsingItem` 的服务端分支施加。
  3. 重复食用刷新**时长**，不叠加**等级**。
  4. 创造模式食用不消耗物品（D-16 的对称处理）。
  5. 食用型作物不参与原版配方、不当动物饲料（D-09）。
- **生命周期**：
  `右键按住 → 食用动画 32 刻 → 进度完成 → 服务端施加效果并消耗 1 个 → 物品数量 −1`

### 2.3 维度二：类别（Category）

类别回答「**这个物品在战斗里干什么**」。类别是一个**多值集合**——一个物品可以同时属于多个类别，每个类别有自己的**判定标准**（满足即可打标签）。

#### 2.3.1 陷阱类

- **正式定义**：部署后处于静默待机状态，直到满足触发条件才产生一次性效果的部署物。
- **判定标准**（全部满足）：① 部署后不主动产生任何效果；② 由「非己方玩家进入指定距离」触发；③ 触发后立即结算并自毁。
- **触发对象**：只针对**非己方玩家**，不处理生物（D-07）。
- **距离度量**：切比雪夫距离（D-20）；唯一例外见 §3.7。

#### 2.3.2 炮台类

- **正式定义**：部署后周期性主动搜索目标并作用于目标的持续部署物。
- **判定标准**（满足其一即可）：① 有明确的攻击行为（发射实体、生成伤害源）；② 被 §plan.txt§ 明确归入炮台类。
- **两条实现路线**：
  - **攻击型炮台**（AttackTurret）：主动索敌并攻击，如 man瓜。
  - **光环型炮台**（AuraProvider）：被 §plan.txt§ 归为炮台类但**没有任何攻击行为**，实际行为是周期性给己方上增益，如激活的火把花、激活的瓶子草。分类标签保留（给玩家看），实现按 `AuraProvider` 走（C-4）。
- **硬挖**：**只有 `pumpkin_turret` 一个方块**被挖掘时需要固定 **10 秒**（200 刻）才掉落（D-13、D-37、§plan.txt§ 第 16 行）；两个光环型炮台（火把花 / 瓶子草）不受此约束，己方按原版正常速度回收（D-14、C-8）。
- **距离度量**：索敌用切比雪夫（D-20）；光环用欧氏半径。

#### 2.3.3 破障类

- **正式定义**：能够**破坏方块**的作物。
- **判定标准**：其产生的主要效果（如爆炸）在正常游戏规则下可以摧毁至少一类原版方块。
- **注意**：破障类不要求「一定能破」，只要求「具备破坏方块的能力」。例如瓜！的爆炸有爆炸抗性阈值（不可摧毁 ≥ 圆石 6.0 的方块），但它确实能破坏大量方块，仍然属于破障类。

#### 2.3.4 buff类

- **正式定义**：为使用者或范围内玩家带来增益 / 减益效果的作物。
- **判定标准**：其主要效果是「施加状态效果」，而不是直接造成伤害或破坏方块。
- **载体**：食用型、投掷型、部署型都可能挂这一类别。
- **命名归一**：§plan.txt§ 第 18 行对该类别的定义文本中写作「buff类」，但第 14~20 行的类别清单里没有「增益类」；幸运浆果条目里写的是「增益类」。全文统一为 **buff类**（见附录 A 的 A-3）。

#### 2.3.5 建造类

- **正式定义**：能够**生成方块**的作物。
- **判定标准**：其效果在世界上写入新的方块，且这些方块是**有实质用途的原版方块**（而不是本模组的部署方块）。
- **区别于破障类**：建造类是「写方块」，破障类是「删方块」。两者互斥地出现在同一物品上时，需要条目明确声明。

#### 2.3.6 伤害类

- **正式定义**：能对玩家造成伤害的作物。
- **判定标准**：其效果链中存在一个明确的伤害来源（爆炸、投射物、召唤实体、虚空伤害等）。
- **注意**：伤害类条目通常在 §plan.txt§ 里同时给出了**伤害上限**，上限是对「该效果最多能打多少血」的硬约束，优先级高于爆炸威力推导出的理论伤害。

### 2.4 类型与类别是两个正交维度

| | 投掷型 | 部署型 | 种植型 | 食用型 |
|---|---|---|---|---|
| **陷阱类** | — | 胡罗贝、赢过输过没死过 | — | — |
| **炮台类** | — | man瓜、激活的火把花、激活的瓶子草 | — | — |
| **破障类** | 育碧服务器、毒育碧服务器、瓜！ | — | — | — |
| **buff类** | 毒育碧服务器、？！菇菇！？、？！棕色菇菇色棕！？ | 激活的火把花、激活的瓶子草 | — | 甜菜！、幸运浆果 |
| **建造类** | 膨胀麦 | — | — | — |
| **伤害类** | 育碧服务器、毒育碧服务器、瓜片子、瓜！、爆竹 | 胡罗贝、man瓜、赢过输过没死过 | — | — |

说明：

1. **类型是「怎么用」，类别是「战斗里干什么」**，两者互不蕴含：投掷型里既有纯伤害的爆竹，也有纯建造的膨胀麦；部署型里既有攻击的 man瓜，也有只发增益的火把花。
2. **13 个条目跨 2 个以上类别**（毒育碧服务器 3 个、瓜！ 2 个、火把花 2 个……），所以类别必须是多重集合，实现上用 `Set<Category>` 表达。
3. **种植型一列全空是结果而非设计遗漏**：种植是一项横切能力（§2.2.3），不占用类型槽位。
4. **15 个条目全部至少命中一个类别**，因此 §1.2 G1 达成。

## 3. 核心系统规则

### 3.1 农产品转换器

#### 3.1.1 定位

转换器是原版作物与改良作物之间**唯一**的通道。它不是合成配方，而是一个**工作方块 + 单槽位 GUI**。

#### 3.1.2 结构

| 项 | 规格 |
|---|---|
| 方块 ID | `farmstorm:converter` |
| GUI 槽位 | **单槽位**输入，无输出槽（转换在取出时结算） |
| 槽位约束 | 只接受「转换配方表」里出现过的物品；其他物品放入直接弹回 |
| 配方载体 | 自定义 `RecipeType`（`farmstorm:conversion`），JSON 数据驱动 |
| 配方方向 | 双向 1:1，一条配方同时声明 A→B 与 B→A（D-11） |
| 经验成本 | 每次转换扣 **3 点经验值**（D-12） |
| 下界之星成本 | 火把花 / 瓶子草**仅正向**（原版 → 激活版）每次额外消耗 **1 个**下界之星；反向免费（D-12） |

#### 3.1.3 转换配方数据格式（简记）

    {
      "type": "farmstorm:conversion",
      "vanilla":  "minecraft:wheat",
      "improved": "farmstorm:puffed_wheat",
      "nether_star": 0        // 仅正向消耗，0 表示不消耗
    }

- 一条配方登记两个方向。
- `nether_star` 只对「原版 → 改良」方向生效；反向恒为 0。
- v0.0.1 共 15 条配方（每个条目一条；瓜片子虽然不可种，但「西瓜片 → 瓜片子」这条通路必须存在）。

#### 3.1.4 结算顺序（伪代码）

    onTakeFromSlot(player):
        recipe = lookup(slot.item)
        if recipe == null: return 拒绝并弹回
        if player.experiencePoints < 3: return 拒绝（不扣等级，不扣经验）
        if recipe.netherStar > 0 and player 未提供下界之星: return 拒绝
        player.experiencePoints -= 3
        if recipe.netherStar > 0: 消耗 1 个下界之星
        result = recipe.otherSide(slot.item)      // 1:1，数量不变
        give(result, player)

#### 3.1.5 关键约束

1. **经验不足则拒绝，绝不扣等级**（D-12）。判定口径是 `player.experiencePoints`（当前级内经验点），不是等级。
2. **每次转换扣 3 点**，与转换数量无关——一次转换 1 个物品。若玩家一次放入整堆，按「每转换 1 个扣 3 点」逐个结算，中途点数不足即停止并保留剩余物品。
3. **双向 1:1**：不产生任何损耗，也不产生任何副产品。
4. **下界之星只对两个作物生效**，且只在正向；这是给「远古植物」设定的入场费。
5. 转换是**数据驱动**的，新增作物不需要改 Java。

### 3.2 播种与收获闭环

#### 3.2.1 规则

1. **每个作物都有播种形态**，与原版播种形态一一对应（D-08）。
2. **收获时按原版比例同时掉落作物与播种物**，形成自给闭环（D-08）。
3. 播种物分两类：
   - **独立播种物品**：`farmstorm:puffed_wheat_seeds`、`farmstorm:power_beet_seeds`、`farmstorm:melon_grenade_seeds`、`farmstorm:pumpkin_turret_seeds`、`farmstorm:awakened_torchflower_seeds`、`farmstorm:awakened_pitcher_plant_pod`。
   - **作物自身即播种物**：其余 8 个，标注为「同名（本身可种）」。

#### 3.2.3 两个特殊映射

1. **毒育碧服务器**：原版毒马铃薯**不是独立作物方块**，它是马铃薯作物的随机产物。因此本模组为它单独注册作物方块与播种物（「自身可种」），脱离原版马铃薯的掉落逻辑。这是「一一对应」原则在原版结构缺位时的显式落地。**已获决策背书：D-32。**
2. **瓜片子不可种植**：原版西瓜片不是播种物，所以瓜片子没有播种形态，也不参与种植闭环。玩家只能通过「瓜！」的落点效果，或转换器（西瓜片 → 瓜片子）获得它。它是 15 个条目中唯一不闭环的一条，这是原版结构决定的，不是缺口。

#### 3.2.4 掉落实现

- 掉落直接复用原版作物方块 loot table 的**结构**（数量区间、时运修正、剪刀等特殊工具判定），只把 `item` 换成改良版的作物与播种物。
- 因此「按原版比例」是一条**结构性引用**，不是把原版数字硬编码一份：原版调整掉落时，本模组不需要跟着改代码。
- 原版参照比例（数量区间）在实现时以原版数据包为准，本模组不复制这些常量。

### 3.3 部署系统

#### 3.3.1 三种附着位置

| 附着位置 | 依附面 | 部署方块落点 | 说明 |
|---|---|---|---|
| 顶部 | 依附方块上表面 | `supportPos.above()` | 立在方块顶上 |
| 底部 | 依附方块下表面 | `supportPos.below()` | 挂在天花板上 |
| 侧面 | 四个水平面 | 沿命中面法线相邻的方块 | 贴在墙面上 |

- 落点方块必须是**可替换的**（空气、水、草、雪层等），否则放置失败。
- 每种作物声明一个 `Set<Attachment>`，超出集合的附着位置直接拒绝，给出失败音效，不消耗物品。

#### 3.3.2 「完整不透明方块」判定

依附方块必须同时满足：

1. `state.isSolidRender(level, pos)` 为真（完整实心立方体，可遮挡光照）。
2. `state.getFluidState().isEmpty()` 为真（没有水 / 岩浆混入）。
3. 不在禁用集合里：可替换方块、`BlockTags` 中的树叶类、台阶、栅栏、墙、玻璃、活板门、地毯、雪层。

不满足则拒绝部署，给出失败反馈，**不消耗物品**。

#### 3.3.3 依附方块被破坏后的悬空规则

| 悬空声明 | 行为 | 适用条目 |
|---|---|---|
| **可悬空**（`floatOnSupportLost = true`） | 依附方块消失后，部署方块原地保留，继续 tick，运行状态不中断 | man瓜、激活的火把花、激活的瓶子草 |
| **不可悬空**（默认，`floatOnSupportLost = false`） | 依附方块消失的下一 tick，部署方块被移除；若配置允许，掉落物品本体（默认允许） | 胡罗贝、赢过输过没死过 |

- 悬空判定在每次 `neighborChanged` 与 `onRemove` 上执行，**每 tick 只判一次**，避免方块更新风暴。
- 「可悬空」的三个条目在 §plan.txt§ 里被逐字写明「依附方块被破坏后可以悬空」，因此这是条目级属性，不是全局规则。

#### 3.3.4 归属记录（Owner）

部署方块对应的 `BlockEntity` 持久化下列字段：

    ownerUuid        : UUID          // 归属者，必填
    ownerName        : String        // 仅用于日志与调试
    supportPos       : BlockPos      // 依附方块坐标
    supportFace      : Direction     // 依附面
    placedGameTime   : long          // 部署时刻
    triggered        : boolean       // 一次性部署物是否已结算（幂等标志）

- **不记录队伍快照**。己方判定在**触发瞬间**用 `TeamResolver` 实时解析归属者的当前队伍，理由见 §7.2。
- `BlockEntity` 必须实现 `saveAdditional` / `loadAdditional`，保证服务器重启后归属与状态不丢。

#### 3.3.5 破坏规则

| 类别 | 破坏方式 | 依据 |
|---|---|---|
| `pumpkin_turret`（攻击型炮台） | 固定硬挖 **10 秒 = 200 刻**，不受工具、附魔、急迫影响 | D-13、D-37 |
| `awakened_torchflower` / `awakened_pitcher_plant`（光环型炮台） | 己方：**原版正常挖掘速度**；非己方：**破坏进度恒为 0**；任何爆炸均无法破坏 | D-14、C-8、D-36 |
| 陷阱类（`blast_carrot` / `fang_trap_cactus`） | 原版挖掘速度 | D-13 反向推论 |
| 火把花 / 瓶子草 追加 | **非己方玩家无法破坏**；己方可正常挖取回收；**任何爆炸都无法破坏** | D-14 |

- `pumpkin_turret` 的硬挖由覆盖 `getDestroyProgress` 返回固定值实现，而非依赖方块硬度：方块硬度会被工具附魔影响，无法保证「恒定 10 秒」。火把花 / 瓶子草的「非己方挖不动」同样在 `getDestroyProgress` 返回 0 实现，对创造模式一并生效（D-36）。
- 破坏时向外掉落**物品本体 1 个**，与部署消耗对齐，形成回收闭环。

### 3.4 投掷系统

| 项 | 规则 | 依据 |
|---|---|---|
| 堆叠 | **16** | D-16 |
| 每次投掷消耗 | **1 个** | D-16 |
| 创造模式 | 不消耗 | D-16 对称处理 |
| 投掷物实体 | 自定义 `ThrowableProjectile` 子类，按作物 ID 携带效果集合 | 实现要求 |
| 运动参数 | 沿用原版雪球：初速 1.5 m/t、重力 0.03、阻力 0.99 | 原版行为 |
| 寿命 | 100 刻（G-6） | 补全 |
| 结算次数 | 每次生成**恰好一次** | 契约 |

**落点判定优先级**（从高到低）：

1. **命中实体**：以 `Projectile#onHitEntity` 的命中点为落点，同时记录被命中实体。
2. **命中方块**：以 `Projectile#onHitBlock` 的命中面内侧方块坐标为「落点方块」，以命中点精确坐标为「落点精确坐标」。
3. **超时 / 掉出世界 / 落入未加载区块**：以投掷物的最后已知位置为落点，若该位置所在区块未加载则**直接作废**，不结算（见 §7.10）。

**落点的两种形态**：

- `BlockPos`：用于「以方块为单位的范围」（膨胀麦的 3×3×3 / 5×5×5）。
- `Vec3`：用于「以半径为单位的范围」（菇菇类的半径 4、瓜！的偏移抖动）。

所有投掷型结算都在服务端执行，并用 `settled` 布尔做幂等保护。

### 3.5 食用系统

| 项 | 规则 |
|---|---|
| 食物属性 | 营养值 / 饱和度修正 / 食用时长，逐条见 §3.8 与各作物规格 |
| 食用时长 | 32 刻（D-29） |
| 效果施加 | `Item#finishUsingItem` → 服务端施加减益 / 增益 |
| 重复食用 | 刷新时长，不叠加等级 |
| 创造模式 | 正常施加效果，不消耗物品 |
| 粒子 | 若条目指定粒子，施加效果时在**被施加者**周围生成 |

**群体效果**：胡罗贝、两个菇菇类与幸运浆果的范围效果作用于「**范围内所有玩家**」，**不筛敌我**——队友、投掷者 / 部署者本人只要站在范围内同样中招。这是**有意的设计，不是遗漏**（D-27）。判定要点见 §3.6.3。

**随机类食用**：幸运浆果为**单次加权抽取**，8 个结果的概率合计恰为 100%，因此每次食用**恰好命中一个结果**，不做多次独立判定。抽取在服务端完成，结果由服务端广播**原版粒子包与音效包**（`ClientboundLevelParticlesPacket` / `ClientboundSoundPacket`）驱动客户端表现，本项目不新增任何网络通道（C-6）。

### 3.6 己方判定

#### 3.6.1 抽象接口

    interface TeamResolver {
        /* 返回玩家的队伍标识；空表示该玩家不属于任何队伍 */
        Optional<TeamId> teamOf(ServerPlayer player);

        /* 双方是否为「己方关系」，必须对称且自反 */
        boolean isFriendly(ServerPlayer a, ServerPlayer b);
    }

**接口契约**（实现者必须全部满足）：

| 编号 | 契约 |
|---|---|
| T1 | **自反**：`isFriendly(x, x) == true` 恒成立 |
| T2 | **对称**：`isFriendly(x, y) == isFriendly(y, x)` 恒成立 |
| T3 | **不要求传递**：队伍可能被解散或改组，因此缓存必须短命（一次判定内有效即可） |
| T4 | **纯读**：实现不得修改计分板或任何外部状态 |
| T5 | **主线程**：只在服务端主线程调用，返回结果在一次 tick 内稳定 |
| T6 | **空队伍**：`teamOf` 返回空时，`isFriendly` 只对自身为真（降级口径，见 §7.7） |
| T7 | **可替换**：v0.0.1 实现可被 FTB Teams 实现整体替换，调用方不得依赖具体类型 |

#### 3.6.2 v0.0.1 实现：`ScoreboardTeamResolver`

    teamOf(player):
        team = player.getTeam()             // 原版计分板队伍，可能为 null
        return team == null ? empty : TeamId.of(team.getName())

    isFriendly(a, b):
        if a.getUUID() == b.getUUID(): return true          // T1
        ta = teamOf(a); tb = teamOf(b)
        if ta.isPresent() && tb.isPresent() && ta.get() == tb.get(): return true
        return false

- 队伍标识取 `team.getName()`，直接映射为 `TeamId`。
- 玩家不属任何队伍时**不报错、不抛异常**，走 T6 降级。
- 该实现是 `TeamResolver` 的**唯一** v0.0.1 实现，通过 `farmstorm.teams.resolver = "scoreboard"` 选中。

#### 3.6.3 调用方约定

| 调用方 | 何时判定 | 判定对象 |
|---|---|---|
| 陷阱类触发 | 玩家进入范围的那一 tick | 归属者 vs 进入者 |
| 炮台类索敌 | 每次索敌扫描 | 归属者 vs 候选玩家 |
| 光环（AuraProvider） | 每次刷新 | 归属者 vs 范围内玩家 |
| 部署物破坏 | 破坏尝试事件 | 归属者 vs 破坏者 |

- 判定对象永远是「**归属者** 与 目标玩家」，而不是「部署方块 与 目标玩家」。
- 归属者离线时，仍按其**最后一次已知的队伍**参与判定（见 §7.2）。
- **敌我筛选只作用于触发条件，不作用于效果范围**：`TeamResolver` 决定「陷阱是否引爆」「炮台是否开火」「光环是否覆盖该玩家」；一旦效果发生，其作用范围对全体玩家生效，**不再做二次敌我筛选**（D-27，见 §3.5）。

### 3.7 距离度量规范

| 用途 | 度量 | 公式 | 依据 |
|---|---|---|---|
| 陷阱类触发 | **切比雪夫** | `max(|dx|, |dy|, |dz|) <= r` | D-20 |
| 炮台类索敌（man瓜） | **切比雪夫** | `max(|dx|, |dy|, |dz|) <= 5` | D-20 |
| 光环（火把花 / 瓶子草） | **欧氏半径** | `sqrt(dx² + dy² + dz²) <= r` | D-20 |
| 投掷型范围效果（菇菇类） | **欧氏半径** | `sqrt(dx² + dy² + dz²) <= 4` | 原文「半径」 |
| 建造类替换范围（膨胀麦） | **立方体边长** | 边长 3 / 5，等价于切比雪夫半径 1 / 2 | 原文「3*3*3 / 5*5*5」 |
| **唯一例外** | **欧氏距离** | 「赢过输过没死过」触发：`sqrt(dx² + dy² + dz²) <= 3` | D-20、C-5 |

**规范条款**：

1. 距离判定原点默认是**部署点方块的中心**（`pos.getCenter()`）或**装置所在方块坐标**，逐条见各作物规格。
2. 比较一律用 `<=`，不使用 `<`。
3. 除本节表格内明确写「欧氏」的，任何新增的距离判定**默认切比雪夫**，并且必须在决策记录里登记例外。
4. 「半径 20 格」「半径 10 格」「半径 4 格」这类措辞一律解释为**欧氏半径**；「切比雪夫距离为 N」一律解释为**切比雪夫半径 N 的方形邻域**。

### 4.1 膨胀麦

物品名称：膨胀麦
英文 ID：`farmstorm:puffed_wheat`（播种物 `farmstorm:puffed_wheat_seeds`）
对应原版作物：小麦
类型：投掷型
类别：建造类
功能：将其投掷出去，在落点处将周围3*3*3的方块（包括空气方块）替换为干草块，当落点周围3*3*3的范围内存在水源方块时，替换范围扩大到5*5*5
物品简介：什么？这不是饼干，这是我们特质的压缩小麦，遇水变大变高，不遇水也变

**实现要点**

- **附着位置**：不适用（投掷型，不产生部署方块）。
- **一次性 / 持续**：一次性。命中即结算，实体随即销毁。
- **触发距离与度量**：以落点方块为中心的立方体，边长 3（干态）/ 边长 5（湿态），等价于切比雪夫半径 1 / 2。「是否存在水源方块」的判定在**原 3×3×3 立方体内**做一次，命中即改用 5×5×5，不再二次判定。水源判定口径为 `FluidTags.WATER` 且 `fluidState.isSource()`。
- **破除条件**：不破坏任何方块。替换范围覆盖空气、流体、实体方块一律直接写入 `minecraft:hay_block`，原方块不做掉落结算。部署方块（本模组）同样会被覆盖，见 §7.11。
- **堆叠**：16（投掷型，D-16）。
- **备注**：范围包含空气，因此效果表现为「凭空补全」一个实心干草立方体；若落点位于未加载区块边缘，按 §7.10 处理。

### 4.2 胡罗贝

物品名称：胡罗贝
英文 ID：`farmstorm:blast_carrot`（播种物同名，本身可种）
对应原版作物：胡萝卜
类型：部署型（方块顶部）

## 7. 异常与边界处理清单

### 7.1 爆炸保护（D-14）

- **受保护对象**：激活的火把花、激活的瓶子草两种部署方块。
- **规则**：任何爆炸（包括本模组的破障类、原版苦力怕、TNT）都无法破坏它们；非己方玩家无法破坏；己方玩家可以正常挖取回收。
- **实现**：在 `Block#getExplosionResistance` 上返回一个远高于任何爆炸威力的值，并在 `BlockEvent.BreakEvent` 上对非己方玩家取消事件。
- **例外**：这两种方块**不受** D-13 的硬挖约束（D-37）——己方按原版正常速度挖掘（C-8）；非己方则无论如何都挖不动。

### 7.2 队伍变更后已部署陷阱的归属

- **规则**：部署方块**只记录 `ownerUuid`，不记录队伍快照**。己方判定在触发瞬间实时解析归属者的当前队伍。
- **后果**：玩家 A 部署陷阱后加入队伍 X，队友 B 走进范围**不会**触发陷阱；A 退出队伍后，B 又会触发。这是预期行为。
- **归属者离线时**：按其**最后一次已知队伍**参与判定——从 `Scoreboard` 的队伍成员表反查，不依赖玩家实体是否在线。
- **归属者被彻底删除**（UUID 不存在于存档）：视为无队伍。
- **归属者没有任何队伍时**：按 D-31 的 `self` 口径，己方集合 = {归属者本人}，其余玩家一律视为非己方（C-9）。

### 7.3 玩家下线 / 死亡时的一次性陷阱

- **规则**：部署方块是**世界对象**，不随归属者下线或死亡消失。玩家死亡不掉落已部署的装置，装置继续按自身状态运行。
- **一次性部署物**：归属者下线期间，若触发条件满足，**照常触发**——判定依据是「范围内的玩家」，与归属者是否在线无关。
- **归属者改名**：只影响 `ownerName` 的显示，判定走 UUID，不受影响。
- **唯一例外**：幸运浆果的 0.1% 创造模式效果在玩家中途下线时**取消且不写入存档**（D-18）。

### 7.4 方块被活塞推动

- **规则**：全部部署方块声明 `PistonBehavior.BLOCK`，**不可被活塞推动或拉动**。
- **理由**：部署方块携带归属者 UUID、依附方块坐标与依附面；一旦被推动，这三个字段会同时失配，且无法在推动后重建正确语义。
- **反向**：依附方块被活塞推动后**不再是原来的位置**，按「依附方块被破坏」处理（§7.9）。

### 7.5 区块卸载

- **规则**：部署方块与 `BlockEntity` 随区块存档一并保存 / 加载，不因区块卸载而丢失。
- **不 tick**：未加载区块内的部署方块不执行 tick，因此陷阱不触发、炮台不开火、光环不刷新。
- **计时器**：光环刷新计时、炮台开火计时、爆竹倒计时在区块卸载时**暂停**，加载后从暂停处继续（用「累计 tick 数」而非「绝对游戏刻」记录）。
- **重新加载后的首 tick**：不补算暂停期间遗漏的刷新次数，只执行一次刷新。

### 7.6 创造模式玩家

| 场景 | 规则 |
|---|---|
| 创造玩家触发陷阱 | **不触发**。陷阱与炮台只锁定非己方且**非创造模式**的玩家，避免失控刷屏 |
| 创造玩家被光环覆盖 | 正常获得效果 |
| 创造玩家投掷 | 正常生成投掷物实体，**不消耗物品** |
| 创造玩家部署 | 正常部署，**不消耗物品** |
| 创造玩家挖掘 `pumpkin_turret` | 仍受 10 秒硬挖约束（D-13 无例外条款） |
| 创造玩家挖掘火把花 / 瓶子草 | 挖不动：`getDestroyProgress` 返回 0 对创造模式同样生效（D-36） |
| 幸运浆果的 0.1% 分支 | 若食用者**本来就是创造模式**，该分支改为「不切换模式、仅播放音效」，且仍占用这一次抽取结果 |
| 旁观者 | 不触发陷阱、不锁定、不被光环覆盖 |

### 7.7 单人无队伍时的降级行为

- **口径**：`farmstorm.teams.untamedFallback = "self"` 时，无队伍玩家的「己方」集合 = {自己}。
- **后果**：其部署的陷阱与炮台对**除自己以外的所有玩家**生效，包括单机里的其他玩家与临时邀请进世界的朋友。
- **另一口径**：把该项改成 `"public"` 时，无队伍玩家视为「与所有无队伍玩家同队」，即无队伍玩家之间互不触发。两种口径都必须在 config 里可选，默认 `self`（G-8）。
- **零玩家场景**：`TeamResolver` 永不对空集合返回 true，任何扫描都为 0 个目标，不产生异常。
- **单人存档**：没有任何其他玩家时，陷阱与炮台在扫描阶段直接短路返回，不做距离计算。

### 7.8 部署点无效 / 依附方块不合法

| 场景 | 规则 |
|---|---|
| 依附方块不是完整不透明方块 | 拒绝部署，播放失败音效，**不消耗物品** |
| 部署点不可替换（已有方块） | 拒绝部署，不消耗物品 |
| 附着位置不被该作物支持 | 拒绝部署，不消耗物品 |
| 依附方块是水源 / 含水方块 | 拒绝部署 |
| 依附方块在本 tick 被破坏 | 部署失败并回滚，不消耗物品 |

### 7.9 依附方块被破坏后的悬空

- **可悬空三件**（man瓜、火把花、瓶子草）：依附方块消失后**原地保留并继续运行**，不产生任何掉落。
- **不可悬空**（胡罗贝、赢过输过没死过）：下一 tick 移除方块，按 `farmstorm.deploy.dropOnSupportLost` 决定是否掉落物品本体（默认掉落，G-9）。
- **依附方块被替换为另一个完整方块**（如被放上另一个方块）：视为依附仍在，不触发移除。

### 7.10 投掷物越过区块边界 / 落入未加载区块

- 投掷物实体本身在实体区块内，随区块加载推进；若投掷物所在区块被卸载，实体随之暂停。
- 结算时若落点所在区块**未加载**，**直接作废**，不做延迟结算——避免区块加载时在玩家看不见的地方发生爆炸。
- 若投掷物飞出世界边界（`y < -64` 或超出世界高度），按超时处理，以最后已知位置结算一次。

### 7.11 方块替换与破坏的优先级

多个效果同时作用于同一方块时，按下列优先级从高到低：

1. **爆炸免疫**（火把花 / 瓶子草，D-14）——最高，任何效果都不能破坏。
2. **爆炸抗性阈值**（瓜片子 6.0、瓜！6.0）——抗性 ≥ 阈值的方块免疫该爆炸。
3. **原版爆炸规则**（育碧服务器威力 4、毒育碧服务器威力 2、幸运浆果威力 1）。
4. **方块替换**（膨胀麦的干草块写入）——**不检查**任何爆炸抗性与免疫，直接覆盖目标方块。
5. **风弹破坏**（爆竹）——按原版风弹规则。

**膨胀麦与部署方块的冲突**：膨胀麦的替换是「写入」而不是「爆炸」，因此**会覆盖**范围内的部署方块（包括火把花 / 瓶子草）。被覆盖的部署方块**不掉落物品**。

### 7.12 瓜！生成的西瓜片归属

- 落点生成 4 个 `farmstorm:melon_slice_bomb` 投掷物实体（不是原版西瓜片，依据 D-09 的「改良作物不再具备原版用途」）。
- 归属者 = 瓜！的投掷者，用于后续的击杀归属与队伍判定。
- 这 4 个实体**不立即结算**：各自按物理运动落地后，走一次标准的投掷型落点流程。
- 若 4 个实体都生成在同一方块内导致重叠，允许重叠，不做分散处理——原文只约束水平偏移范围。

### 7.13 幸运浆果创造模式分支的特殊处理

| 场景 | 规则 |
|---|---|
| 正常流程 | 记录 `previousGameMode` → 切换 `CREATIVE` → 1800 刻后强制还原 |
| 玩家中途下线 | **取消该效果，不写入存档**（D-18）；重新登录后保持原游戏模式 |
| 玩家中途死亡 | 保持创造模式至计时结束（创造模式不会死亡） |
| 计时结束后玩家已是旁观 | 强制还原为记录的原游戏模式 |
| 服务器重启 | 计时记录**不持久化**，重启后视为已取消，玩家保持当前模式 |
| 同一玩家重复命中该分支 | 重置计时器为 1800 刻，不叠加 |

### 7.14 转换器方块被破坏 / 输入槽残留

- 转换器被破坏时，输入槽内的物品**全部掉落**为物品实体（不漏物品）。
- 破坏时不返还已消耗的经验点。
- 转换过程中断（玩家关闭 GUI）不产生部分转换：转换是「取出即结算」的原子操作。

### 7.15 多光环叠加与临时附魔冲突

- **多光环叠加**：同一玩家同时处于多个光环范围内时，**各自独立刷新**。同名效果的等级取**最高**、时长取**最长**，不叠加等级。
- **临时附魔**：火把花的火焰附加 1 是临时附魔。若玩家同时身处两株火把花范围，只附加一次。离开全部范围或到期后移除，**保留原有附魔**（D-15）。
- **已有火焰附加**：若剑本身已有火焰附加 II，临时附魔不降级、不覆盖，保留原值。
- **切换手持物品**：光环每次刷新都重新检查手持物品，切走剑即移除临时附魔。

### 7.16 服务端权威与客户端预测

- **不预测**：所有部署、触发、爆炸、效果施加、经验扣除都由服务端决定，客户端不做预测。
- **粒子与音效**：投掷型结算、光环刷新、炮台开火通过**原版**粒子包与音效包通知客户端（C-6），客户端只播表现。
- **掉包容忍**：客户端丢包最多导致缺少一次表现，不影响任何状态。

### 7.17 堆叠与消耗的边界

| 场景 | 规则 |
|---|---|
| 投掷最后一格 | 正常投掷，物品槽清空 |
| 创造模式投掷 / 部署 / 食用 | 不消耗物品 |
| 部署失败 | 不消耗物品 |
| 转换经验不足 | 不转换、不扣经验、不扣等级 |
| 批量转换中途经验耗尽 | 已转换的结果发放，剩余物品留在槽内 |
| 堆叠超过上限 | 由 config 改小堆叠上限时，超出部分在下次堆叠合并时溢出到背包，不做强制拆分 |

### 7.18 游戏规则与事件取消

- 影响方块的爆炸统一走原版 `Explosion`，因此自动遵守 `mobGriefing` 与 `doTileDrops` 等游戏规则。
- `mobGriefing = false` 时，全部破坏方块的爆炸不破坏方块，但**伤害照常**。
- `keepInventory` 不影响部署方块（它们不是玩家掉落物）。
- 部署方块的破坏走 `BlockEvent.BreakEvent`，可被其他模组取消；被取消时视为部署仍存在。
