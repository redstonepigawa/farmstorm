## §1 R8 · 控制终端（D-020 ~ D-038）

**三秒能说清的变化**：据点核心（outpost_core）的 54 格库存里堆着的胡萝卜、南瓜、小麦，v0.2.8 只能靠玩家一件一件右键塞进机器；本版多一台方块，点两个按钮之一，它每 1 秒替玩家往空着的机器里各塞 1 个，从核库存里扣（D-016 第 ① 条、D-032）。

### 1.1 玩家看到什么

- 金属外壳：硬度 5.0、爆炸抗性 1200、铁砧音效、活塞推不动，与农作物培养器（cultivator）、农作物转换器（crop_converter）同一组七项（D-021、`FarmstormBlocks.java:75-82` / `:105-112`）。
- 正面 / 侧面 / 顶面各是一段 **24 帧**循环动画，每帧 2 刻，一轮 24 × 2 = 48 刻 = **2.4 秒**；底面是 **32×32** 静态图。每帧实际 32×32，动画 PNG 是 **32×768** 纵向帧条，四张 PNG + 三个 `.mcmeta` 共 **7 个手放文件**（D-023）。
- 动画与方块状态无关：放下去就在播，开不开面板、选没选模式都一样播；素材包 README 把这套动画称作「循环装饰示意，不代表模组内真实库存、选择状态或操作进度」。方块带水平朝向、正面朝放它的玩家，blockstate 恰好 **4 个 variant**，没有「工作态」这类属性（D-022 及其补充、D-023）。
- **右键一定开界面**：标题「控制终端」，里面**槽位 0 个**，只有两个按钮（培养模式 / 转换模式）与一行状态文字（D-028、D-034）。
- 未绑定时状态行「未绑定」、两个按钮置灰且点了毫无反应；已绑定时「已绑定」、两个按钮可点；点亮的那个再点一次，两个全灭回到关闭。标题加这四条文案就是新增 7 个语言键里的 5 个（1 个 `container.` 标题键 + 4 个 `gui.` 键），语言键 321 + 7 = **328**（D-018、D-028、D-031；`zh_cn.json` 的 `container.farmstorm.outpost_core`、`gui.farmstorm.core_hud.self` 是同族先例）。
- 绑上核后有**一条绿线**，主线两端各挂一个 0.25 格小框：终端绿 (0.30, 0.85, 0.30)，培养器青 (0.30, 0.85, 0.90)，转换器红 (0.92, 0.22, 0.22)，三组各自独立。线只发给站在机器 3×3 区块内的玩家——「看不见线」与「没绑上」是两条判据。终端占核那 **24** 个名额里的 1 个，绑定范围也同一条判据：核心所在区块 + 周围 8 区块 = 3×3 区块 / 48×48 格（D-026、D-027、D-036、D-038、`CultivatorLinkRenderer.java:51-53` / `:59-61` / `:67`、`OutpostCoreBlockEntity.java:89` / `:537-543`、`CultivatorLinkBroadcaster.java:211`）。
- 合成 3×3 产出 1 个：四角玻璃（glass）、四边铁锭（iron_ingot）、正中红石粉（redstone），图样 `GIG` / `IRI` / `GIG`，与培养器 `IGI` / `GRG` / `IGI`（`ModRecipeProvider.java:122-124`）、转换器 `III` / `GRG` / `III`（`:100-102`）三者两两不同，材料仍是 4 铁 + 4 玻璃 + 1 红石（D-029）。
- 这条配方剥掉解锁进度（`ModRecipeProvider.java:174-201` 的 `recipeWithoutAdvancement`）：合成配方 4 → 5、配方 JSON 25 → 26、进度仍是 **16**；拆它掉 1 个终端物品（方块战利品表 28 → 29），挖它要石镐及以上（D-018、D-029、见 §2）。

### 1.2 系统怎么运作

只写玩家能自己推出来的因果链，字段与算法在 08 号：

1. 模式存在这台方块自己身上（终端方块实体的 NBT）：一个核上挂两台终端，各自的模式互不覆盖（D-030）。
2. 模式三选一（关闭 / 培养 / 转换）且**互斥**，初始是关闭；不存在「两个都开」的第四种状态，也没有「必须始终有一个模式」（D-031）。
3. 选了模式之后服务端每 **20 刻（1 秒）** 跑一轮；20 是代码常量，server config 仍是 **175** 个键，找不到投料节拍这个键（D-032、`facts-A §5`）。
4. 一轮里每台**空着投入槽**的目标机器最多收到 1 个，槽里有货的整轮跳过（D-032、`CultivatorBlockEntity.java:152-154`）。
5. 收什么由机器自己那条准入闸说了算、终端不自建第二份名单：培养模式问 `admissible`（`CultivatorBlockEntity.java:143-149`，本版起不再排除史诗输出，见 §3），转换模式问转换器的准入（`CropConverterBlockEntity.java:152-160`，命中一条转换配方就收）（D-033）。
6. 判据只有一个来源，于是数据包新增一条转换配方时，培养模式**自动多收一个投入物**，终端不用重做（D-033 补充、D-043）。
7. 关闭态什么都不发生：不搬、不扣核库存（D-031）。
8. 绑定范围与另外两台同一条判据（3×3 区块 / 48×48 格），超范围既不绑也不投（D-027）。
9. 终端不持有任何物品：拆它地上只有 1 个终端物品，机器槽里那件由机器自己在拆除时交出来（`CultivatorBlock.java:141-148`、`CropConverterBlock.java:144-150`、D-025）。
10. 名额是共享的 24 个：拆掉一台之后，名额由惰性清理与每 100 刻一次的补绑扫描收回（`OutpostCoreBlockEntity.java:111` / `:450-469` / `:608-656`、D-026）。

### 1.3 与上一版（v0.2.8）的差别

| 项 | v0.2.8 | v0.3.0 |
|---|---|---|
| 核库存到机器 | 右键核开 54 格界面取出，再右键机器一件一件塞 | 多一条自动通道：终端每 1 秒给每台空槽机器塞 1 个 |
| 连线颜色种类 | 青（培养器）、红（转换器）两色 | 三色，多一种绿（终端）；既有两色的三个分量一个字节不动 |

| 处理方块的挖掘门槛 | 培养器挖不出、转换器木镐可挖 | 三块统一到石镐起（见 §2） |

## §2 R9 · 处理方块的可挖门槛（D-039 ~ D-041）

**三秒能说清的变化**：农作物培养器在 v0.2.8 里**挖了什么都不掉**，拆一台少一台；本版起拿石镐挖它掉一个培养器给你，控制终端同理；农作物转换器以前木镐就能挖出，现在要石镐。

### 2.1 玩家看到什么

- 拿木镐（或徒手）挖三个处理方块（培养器、转换器、控制终端）：方块**照样碎掉消失**，地上**不掉东西**（D-040 的判据措辞）。
- 拿石镐及以上（本版保证石镐这一档）挖同样三块：碎掉，地上 1 个对应方块物品（D-039、D-040）。
- 三块都在「镐类可挖」的名单里，用镐比徒手快；这条名单只管速度，不管掉不掉（D-039）。
- 金镐落在哪一档本版**不写断言**：1.20.1 由 `TierSortingRegistry` 与工具等级共同决定，本仓读不出金镐的真值，留给 08 号验收实测（D-041、06 号 §8 第 1 条）。
- 创造模式拆这三块一律不掉落；拆机器前放在投入槽里的那一件照旧掉出来——门槛只决定「方块本体掉不掉」。它们仍是 `farmstorm:processing_block` 的成员，核仍按标签发现它们（`CultivatorBlock.java:141-148`、`CropConverterBlock.java:144-150`、`ModBlockTagsProvider.java:45-47`、`OutpostCoreBlockEntity.java:891-892`、D-024）。

### 2.2 系统怎么运作

1. 两道闸分工：`#minecraft:mineable/pickaxe` 管**挖速**，`#minecraft:needs_stone_tool` 管**算不算正确工具**；只加前者木镐挖得慢但照样掉，只加后者挖速仍是徒手级（D-039、D-040、`facts-B §5.1`）。
2. 1.20.1 的判定链与 1.21.1 不是同一套符号：`ForgeHooks#isCorrectToolForDrops` 先读方块的 `requiresCorrectToolForDrops`（`ForgeHooks.java:226-232`），真正算账的是 `DiggerItem` 与 `TierSortingRegistry`（`DiggerItem.java:64-82`，`NEEDS_STONE_TOOL` 分支在 `:74`）（`facts-B §5.2`）。
3. 「方块照样被移除」与「掉不掉」是两个独立调用：`removeBlock` 在前（`ServerPlayerGameMode.java:253`），掉落只在正确工具为真时发生（`:255`）；所以木镐的判据是**掉落 0 个**，不是「破坏不了」（D-040 补充）。
4. v0.2.8 的培养器两头都写死了：既要求「正确工具才掉」（`FarmstormBlocks.java:105-112`），又不在任何 `mineable/*` 名单里（`ModBlockTagsProvider.java:49-63` 现有 10 个成员，没有它）——于是任何工具都不算正确工具，结果就是永远不掉落。本版把三块补进镐类名单（成员 10 → 12）再补一条「石质及以上」（成员恰为那三个）；掉落物由战利品表给：培养器 `ModLootTableProvider.java:138`、转换器 `:135` 各一张，终端按同形写法新增一张（28 + 1 = 29，D-018、D-039、D-040）。

### 2.3 与上一版（v0.2.8）的差别

| 方块 | v0.2.8 木镐 | v0.2.8 石镐 | v0.3.0 木镐 | v0.3.0 石镐 |
|---|---|---|---|---|
| 农作物培养器 | 不掉落（任何工具都不掉） | 不掉落 | 不掉落（方块仍被移除） | 掉 1 个 |
| 农作物转换器 | 掉 1 个 | 掉 1 个 | 不掉落（方块仍被移除） | 掉 1 个 |
| 控制终端 | 不存在 | 不存在 | 不掉落（方块仍被移除） | 掉 1 个 |

## §3 R10 · 史诗类作物可培养（D-042 ~ D-044）

**三秒能说清的变化**：手里拿着火把花（torchflower）、瓶子草（pitcher_plant）、甜浆果（sweet_berries）、金苹果（golden_apple）右键农作物培养器，v0.2.8 是「什么都不会发生」，本版会收下；30 秒后核里多出 4 个同一物品（1 个金苹果进，4 个金苹果出）。

### 3.1 玩家看到什么

- 手持这四件任意一件右键培养器：槽里进 1 个，与其它投入物是同一个动作（D-042）。
- 30 秒后核里出现两组：投入物 × 2 + 对应种子 × 2（产出数量默认 2、培养周期默认 600 刻，`FarmstormConfig.java:952-957`、`CultivatorBlockEntity.java:261-267`）。「对应种子」表只列 **6 条**（小麦 / 甜菜根 / 西瓜片 / 西瓜 / 南瓜 / 平凡韭菜，`CultivatorBlockEntity.java:270-276`），表外一律是它自己（`:285-288`）：这四样不在表里，于是第二组装的就是它本身——甜浆果 4 个甜浆果、金苹果 4 个金苹果。
- 南瓜不在本版新增之列：南瓜从 v0.2.8 起就能进培养器，它在对应种子表里，那条一直是 2 个南瓜 + 2 个南瓜籽；man瓜（pumpkin_turret）是普通档，不在四条史诗档案里（`CultivatorBlockEntity.java:270-276`、`CropProfile.java:73-105`、`facts-A §1.2` 的品质 11 / 7 / 4、D-042 补充）。
- 这四件在 v0.2.8 里能进转换器、不能进培养器，本版两边都收，这个不对称消失（`CropConverterBlockEntity.java:148-149`、D-042）。
- 培养器量产的是**原版投入物**，不是改良作物本身：man瓜、激活的火把花（awakened_torchflower）、激活的瓶子草（awakened_pitcher_plant）、幸运浆果（lucky_berry）、狂野苹果（wild_apple）仍只从转换器或交易来；手持改良作物右键培养器仍然无反应，它们是转换的**输出**、不是任何一条配方的输入（`CultivatorBlockEntity.java:141`、D-043、D-044）。

### 3.2 系统怎么运作

1. 培养器的准入判据只有一条：命中一条转换配方就收；v0.2.8 后面还挂了一句「且该配方的输出不是史诗档」，本版删掉这一句（D-042、`CultivatorBlockEntity.java:148` 逐字如此）。
2. 被那句话挡在外面的恰好 4 条：火把花 → 激活的火把花（`ModRecipeProvider.java:66`）、瓶子草 → 激活的瓶子草（`:67-68`）、甜浆果 → 幸运浆果（`:74`）、金苹果 → 狂野苹果（`:78`）；四条输出的档位见 `CropProfile.java:73-75` / `:76-78` / `:88-89` / `:102-105`。
3. 21 条转换配方里被挡掉的正好 4 条，其余 17 条一直能进培养器，南瓜 → man瓜 就在这 17 条里（`ModRecipeProvider.java:57-83`、21 − 4 = 17、D-042 补充）。
4. 判据仍然只有一处：不写物品白名单、不按档位另开分支、终端也不另存一份；数据包加一条配方，这四样的名单一起扩。产出倍率不动：仍是「投入物 × 产出数量 + 对应种子 × 产出数量」两组，不因放行改倍率、不因放行加成本（D-043、D-044、D-033 补充）。

### 3.3 与上一版（v0.2.8）的差别

| 项 | v0.2.8 | v0.3.0 |
|---|---|---|
| 培养器对火把花 / 瓶子草 / 甜浆果 / 金苹果 | 右键无反应 | 收下 1 个，30 秒后给 4 个同一物品 |

## §4 R11 · 膨胀麦干草块不掉落（D-045 ~ D-049）

**三秒能说清的变化**：膨胀麦（puffed_wheat）砸下去铺出来的那片干草块（hay_block），v0.2.8 拆了能捡回干草块本体（等于白拿材料）；本版拆了什么也不掉。

### 4.1 玩家看到什么

- 把膨胀麦丢到地上，落点周围一片**原版干草块**被铺出来：干态边长默认 3、遇水默认 5（`FarmstormConfig.java:350-355`），实现按 `edge / 2` 取半径（`PuffedWheatProjectile.java:105`）。
- 拆这片里的任意一块：方块碎掉，**地上什么都不掉**，也没有经验（原版干草块本来就是 0 经验）。拆村子里本来就有的干草垛、或玩家手放的干草块：照旧掉干草块本体；拆压缩干草块（compressed_hay_block）也照旧掉，不在本版范围（`CompressedPuffedWheatProjectile.java:34-37`、D-047、D-048）。
- 被膨胀麦**跳过**的格子（爆炸抗性太高、或格子里本来就有方块）从来不记，之后拆了照旧掉；所以那片干草块里可能掺着旧方块（`PuffedWheatProjectile.java:113-118`、D-046）。
- 记录认的是**格子**而不是方块：那一格只要还没被拆过记录就还在，被拆过一次就删掉，之后往同一格再写干草块也不会自己重新登记，除非膨胀麦再砸一次（D-045、D-048）。

### 4.2 系统怎么运作（1.20.1 走战利品修饰器，不走事件）

1. 1.20.1 **没有**方块掉落事件：`BlockEvent` 的嵌套类清单里没有 `HarvestDropsEvent` / `BlockDropsEvent`（`facts-B §1`）。本版不走「监听破坏、清空掉落」，改走**全局战利品修饰器**：拦截点在战利品表开箱那一刻（`LootTable.java:118` → `ForgeHooks.java:1196-1198`），方块照旧被移除、经验照旧结算（D-047、D-048）。
2. 要点一「坐标记录」：写入循环在 `setBlock` **成功之后**把这一格记进服务端存档（`PuffedWheatProjectile.java:119`、D-046），键是 `BlockPos.asLong`，落在 `farmstorm_puffed_hay` 这份 `SavedData` 上；1.20.1 的签名是 `save(CompoundTag)` 与三参 `computeIfAbsent(Function, Supplier, String)`（`facts-B §4`、先例 `OutpostCoreIndex.java:76-79`、`TrapFifoIndex.java:59-60`、D-045）。登记前再判一次 `Blocks.HAY_BLOCK`，否则压缩膨胀麦会把压缩干草块也记进去（`CompressedPuffedWheatProjectile.java:34-37`、D-046 补充）。
3. 要点二「命中即整表替换为空」：修饰器从 `LootContextParams.ORIGIN` 取落点——1.20.1 这个参数是 `Vec3`，要转 `BlockPos` 才能查记录（`LootContextParams.java:18`、`facts-B §2.4`）——命中就把本次掉落**整表替换成空表**并删掉该条记录；这不是「取消破坏」，被替换的只有掉落物列表（D-048、`facts-B §2.5`）。
4. 要点三「清单必须登记」：数据文件是**两份**——修饰器本体 `data/farmstorm/loot_modifiers/puffed_hay.json`，加清单 `data/forge/loot_modifiers/global_loot_modifiers.json`（命名空间固定 `forge`）；漏登记 ⇒ 修饰器**静默不生效**，没有日志、没有编译错。注册面因此多 1 项 `global_loot_modifier_serializers`（0 → 1，注册面 91 → 96、11 类 → 12 类），Java 多 3 个文件（修饰器类 / 注册类 / datagen provider），loot modifier 数据文件 0 → 2（`LootModifierManager.java:53` / `:75`、D-047、D-049、D-018、08 号 RT-011）。
5. 事件监听仍是 **9** 条，一条不加（拦截面换成了战利品修饰器）；创造模式挖掉不触发战利品表，于是记录不会被消费（`FarmstormGameEvents.java:67-79`、D-047、D-048 补充、06 号 §7 第 8 行）。

## §6 已知影响（12 条）

以下 12 条都会被玩家感知到，逐条写明它**不是缺陷**，而是某条决策的后果；前 10 条与 1.21.1 的 65 号同构，后 2 条是 1.20.1 侧特有的。

1. **史诗四件从「交易专供」变成「可量产」**：四件不在对应种子的 6 条表里，产出批次的两组装的是同一个物品，于是 1 个进、4 个出（金苹果最显眼）。这不是缺陷，是 D-043 的后果——准入判据只剩「命中一条转换配方」，产出面按 D-044 一个倍率都不动。
2. **农作物转换器从「木镐可挖」变成「石镐起」**：木镐挖会碎但不掉。这不是缺陷，是 D-040 的后果——用的是原版那条工具等级标签，一加上去就对三个成员同时生效。
3. **农作物培养器从「挖不掉」变成「石镐起可挖」**：v0.2.8 拆一台是纯损失，本版掉落 1 个。这不是缺陷，是 D-039 的后果，而且它正是第 ② 条需求要盖住的既有缺口。
4. **协议串 `"1"` 升到 `"2"`，跨版本不互通**：装 0.3.0 的客户端连 0.2.8 的服务器（或反过来）会在握手阶段被判为不匹配。这不是缺陷，是 D-037 的后果——连线类型多了一个线上码（D-035），与其让旧客户端画错色，不如在握手就拒。
5. **老存档里已有的膨胀麦干草块照旧掉落**：升级前铺出去的干草块不在记录里。这不是缺陷，是 D-046 的后果——记录只从「本版第一次写入成功」开始攒，本版不做回溯扫描。
6. **未绑定也能右键开面板**：机器那套「任一闸不过 = 右键无反应」在终端这里不成立。这不是缺陷，是 D-028 的后果——机器是「往槽里塞东西」，无反应是它唯一说得通的拒绝；终端是「打开一个界面」，无反应等于让玩家拿着新方块学不到任何东西。
7. **终端占掉一个绑定名额**：想同时挂 24 台机器的核，加了终端就得少挂 1 台。这不是缺陷，是 D-026 的后果——终端与两台机器共用同一份名单，`kindOf` / `hasCultivator` / 惰性清理三条既有不变量才不会分叉成两套。
8. **拆下再放回，模式回到关闭**：模式只存在方块实体的 NBT 里，不掉进方块物品。这不是缺陷，是 D-030 的后果——本版不给终端物品加携带模式的数据组件。
9. **记录跟着格子走，不跟着方块走**：那一格只要还没被拆过记录就还在；把干草块换成别的方块再换回来，拆了仍不掉落。这不是缺陷，是 D-045 的后果——记录键是位置，原版干草块没有我方方块实体可以挂第二份真相。
10. **创造模式破坏不消费记录**：创造模式挖掉一块被记录的干草块不触发战利品表，记录不被删除。这不是缺陷，是 D-048 的后果；代价上限是「一格干草块不掉落」，不影响其它格子。
11. **战利品修饰器只影响 `minecraft:blocks/hay_block` 一张表（1.20.1 特有）**：本平台没有方块掉落事件，拦截只能挂在战利品表上，作用面因此是一张表而不是「某一次破坏」。这不是缺陷，是 D-047 的后果——代价是清单漏登记会静默失效（B-28），换来的是不动方块移除路径、不与第三方的破坏事件处理器互相干扰。
12. **装饰动画与状态无关（1.20.1 特有）**：三面各是一段自播的 24 帧动画，靠贴图自带的 `.mcmeta`，不按 `working` 之类的属性切模型，所以玩家看不到「工作中 / 待机」的视觉差别。这不是缺陷，是 D-022 与 D-023 的后果——素材包 README 明说这套动画是循环装饰示意，与库存、选择状态、操作进度无关。

## §7 不做的事

- 控制面板不显示核库存：面板 0 槽、不搬物品，核里有什么仍然要右键核去看（D-034）。
- 终端不搬运机器产出：产物由机器自己送回核，终端只负责「核 → 机器」这一个方向（D-033）。
- 不改干草块外观、不回溯老存档：落点仍是原版干草块，不给历史干草块补记录（D-045、D-046）。
- 不加 config 键：投料节拍是常量，server config 仍是 175 个、client config 仍是 3 个（D-032、`facts-A §5`）。
- 不给培养器与转换器加菜单：那两台仍靠右键直接塞（`CultivatorBlock.java:111-129`、`CropConverterBlock.java:114-132`）。
- 不改既有两个连线颜色的三个分量：只追加绿色一组（D-038）。
- 不新增第三个网络包：面板状态走 `ContainerData`，连线走既有 payload（D-034、D-035）。
- 不写 Mixin：本版 Mixin 计数仍是 0（06 号 §0.4）。
- 不把终端做成远程操控：它只把核里的东西投进 3×3 区块内的机器（D-027）。
- 不给终端加「工作态」属性、不按状态切贴图：三面动画自己播，代码侧 0 行（D-022、D-023）。
- 不改容量：`outpost_core.cultivatorCapacity` 仍是配置项、默认 24（D-026），`outpost_core.storageSlots` 钉死在 54（`FarmstormConfig.java:939-941`）。
- 不把干草块记录做成方块实体：原版干草块没有我方方块实体，只能挂存档记录（D-045）。
- 不给三个处理方块加更高的门槛：只到「石质及以上」，不加铁质或钻石档（D-040）。
- 不动镐类名单里既有的 10 个成员：只追加两块，其余条目一行不改（D-039）。
