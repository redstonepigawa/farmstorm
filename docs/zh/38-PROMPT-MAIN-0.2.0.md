## 0. 你面对的是什么

v0.2.0 不是「在 0.1.1 上再加几个东西」。它是**第一次推翻上一版自己的核心机制**：0.1.1 的耕地绑定制（D-134 ~ D-140：一块耕地只归一个核、每核 16 块、额度 = 16 × 己方核数）被整体停用；那个「16」没有消失，而是**换了所指**——从「每核多少块耕地」变成「每核多少个培养器」（D-165），键也从 `outpost_core.farmlandBonus` 换成 `outpost_core.cultivatorCapacity`。所以你打开的是这样一个版本：**绑定对象换了、核心变成箱子、两条老获取路径（种植与转换器）同时断掉、作物第一次有了品质。**

停用的方式是「只注释调用点」（裁定 #3）：两个类（`FarmlandLedger` 555 行 / `FarmlandGuard` 225 行）一行不改、仍在源码树里、仍编译，`farmstorm_farmland.dat` 不读不写不删。**读懂「注释 ≠ 删除」是这一版的第一道门槛**，读歪的人会去删代码、删存档、删方块，那三件都不在本版范围内（§1 的 HC-116 ~ HC-118）。

**四处全项目第一次**（每处都按 L 计工时，都不许「照着抄一个类」）：

**三条最贵的事实**（背下来，它们决定了本版一半的返工）：

1. **54 与 16 不是一个东西**：54 是核心的**格子数**（双箱 = 27 × 2），16 是每核的**培养器名额**。混一个，菜单会崩、文档会错、`RT-44` 会同时命中两处（裁定 #8、34 §7 墓碑 3）。
2. **「不能种」要在两条路径上各断一次**：`ModifiedCropItem#isPlantableSoil` 与 7 个 `SeedItem#useOn`。只堵前者，7 个独立种子照样能在耕地上种出作物（D-152、RT-48）。
3. **品质只在一处定义**：22 条档案的 `tier` 同时喂交易抽样、培养器准入、幸运浆果池三处；错一条，三处一起错（RT-49）。

## 7. 回报格式

每份回报固定四段，**顺序不变、缺段即未完成**：

```
## 结论
一句话：做了什么、对应哪几个编号（F 号 / D 号 / 36 §3 行号 / 验收号）。
禁止写「完成」「正常」「没问题」——那不是结论。

## 证据
每条判据三行：命令原文 → 关键输出（原样一至三行）→ 编号（HC-xx / N-xx / 36 §8 #n / 35 §12 B-nn）。
计数类判据给「改前实测值 / 改后实测值」两个数（陷阱 20）。
改动面给 `git diff --stat` 的文件清单（一任务一提交，多一个文件就是超范围）。
存档类判据给 `/data get block <pos>` 的键摘录或停服后的文件读数。

## 未决问题
拿不准的、文档之间冲突的、需要作者拍板的。没有就写「无」——不许省略这一段。

## 下一步
按 37 号依赖图，下一个该做的任务号；以及本轮**没做**但已经看见的问题（只登记，不动手）。
```

三条约束：

1. **证据必须是可观察的**：日志行、命令读数、`git diff`、`jar tf`、存档 NBT、游戏内读数。日志超过 20 行只留**第一条错误**与**总结行**。
2. **每条断言都要落编号**：没有编号的断言按「未验证」处理；写了编号但没给读数的，按「未跑」处理。
3. **不许只贴文件内容**：`git diff` 只贴改动的那几行，不贴整文件；日志只贴命中行。回报是给下一个人做判断用的，不是存档。
