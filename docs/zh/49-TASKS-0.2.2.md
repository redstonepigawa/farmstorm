## 0. 阅读约定

### 0.1 任务粒度（五条）+ 四条本版读数纪律

一个任务 = 一次可独立提交、可独立验证的改动。五条判据沿用 43 号 §0.1（源头是 37 号 / 31 号），本版不改写、只重述：

1. **一个任务 = 一次可独立提交、可独立验证的改动。**
2. **提交后 `.tools\gw.cmd build` 退出码 0**，且不依赖同批次里尚未提交的任务。
3. **每个任务自带至少一条可观察断言**，断言里必须出现具体数值、键名、路径或日志片段。
4. **回滚该提交不会让其它已完成任务失效**（只影响依赖它的后续任务，依赖写在 §1 的「依赖」列与任务标题行）。
5. **不跨 Phase 边界**：一个任务的交付物全部落在它所属 Phase 的名称范围内。

四条**本版特有**的读数纪律（写在这里，任务里不再重复）：

- **行号一律 UTF-8 口径**：本机默认 `Get-Content` 会把无 BOM 的 UTF-8 中文读成 GBK 并吞掉换行（同一份 `42-TECH-0.2.1.md` 从 872 行读成 647 行），行号随之全错（48 号 §0.2 第 4 条）。本文所有行号按 `[IO.File]::ReadAllLines($p, UTF8)` 与 `grep`（UTF-8）复核过，与 48 号逐处对过。
- **「原版」与「本仓」分两棵树**：`net/minecraft/**` 在 `.scratch/p25a/src/`，本仓在 `src/main/java/com/dashpig/farmstorm/`。凡写「`src/` 下命中 0」的验收，**不许**写成全仓 `grep -r`（那会把反编译源算进来，48 号 §10 第 3 条）。
- **数 toml 只认 `run/config/farmstorm-server.toml`**：仓里另有几十份 `run-*/config/` 旧副本；拿错一份会得出「键数不是 176」的结论。本文件数三个数：段 `60` / 键 `176` / `:753 = 2`、`:765 = 16`。
- **不写「正常」「手感」**：判据只能是五类——计数（文件数 / 键数 / 命中数）、日志行、`/data get` 读数、源码 grep 字符串、像素比对。

### 0.2 复杂度与人日换算（S/M/L → 0.5/1.5/3.0）

换算口径与 43 号 §0.2 完全一致，本版不调整：

| 复杂度 | 含义 | 折算人日 |
|---|---|---|
| S | 单文件或纯数据；≤ 1 个类，或 ≤ 3 个文件里的字面量替换 | **0.5** |
| M | 2 ~ 4 个文件，跨 1 ~ 2 个包，或新增 1 个完整行为实现 | **1.5** |
| L | ≥ 5 个文件或跨 3 个包，含运行期状态机 / 序列化 / 容器契约 / 渲染管线 / 跨类接口改造 | **3.0** |

本版 19 个任务按此分布：**S 8 / M 9 / L 2**，折算 `8 × 0.5 + 9 × 1.5 + 2 × 3.0 = 4.0 + 13.5 + 6.0 = **23.5 人日**`（不含缓冲）。

**计时的四条口径**：

1. 凡「全仓 0 先例」（F-275 的 `PoiType`、F-277 的 `VillagerProfession`、F-276 的 `TagsProvider<PoiType>`）按比「改一个既有类」高一档计，理由是一次性要把注册表、数据包产物、接线三处同时押对，返工概率高于普通 M。
2. 凡「原子提交」（F-268：注册 + 断言 + 8 处注释 + 工具期望面）按 M 计——它的四个文件互不相邻，但**不许拆**（§0.5 死命令 1）。
3. 凡验收任务（F-283 / F-284）不按「跑一遍」估时，按 L 计：30 条里 8 条要开界面、2 条要重生成 config、4 组必须成对跑。
4. 凡「只改注释」（F-269 的模型注释、F-274 的八处注释、F-281 的两处注释）不计入独立 S，一律并进它所在的行为任务——注释与代码分两次提交就留下「注释说 16、代码是 24」的窗口（`BRIEF` §3.4 #18 的同一条纪律）。

### 0.4 一个任务 = 一个提交

1. **一个任务一个提交**，提交信息以任务号开头（`F-268: …`）；提交内容与「涉及文件」逐条对齐，多一个文件就是超范围。
2. **不夹带既存瑕疵的顺手修**：48 号 §10 登记的 13 条差异里，属于「登记不改」的部分（`CultivatorBlock:73-84` 的旧注释、`OutpostCoreBlockEntity` 的 `removeCultivator` 死代码、`.scratch/` 里的 `neoforge.mixins.json`、42 号 §1.2 的行号漂移）本版**一条都不改**；它们出现在「易漏点」里是为了「别顺手改」，不是待办。
3. **回滚粒度 = 提交粒度**：每个任务的验收断言必须在只回滚这一个提交之后仍然描述得通（不依赖同批次的其它提交）。
4. **上游一字不改**：写作期发现的 46 / 47 / 48 差异全部登记在 §5 的 A-82 ~ A-91，**只登记、不修改**上游文件；任务里引用上游时写全节号（`48 号 §2.3.5`），不转述实现细节。
