# 任务书 V002-F-70 · 球内候选枚举与逐格掷火 / 岩浆块

## 目标（`13-TASKS-0.0.2.md` §3 F-70）

- 复杂度 M ｜ 1.5 人日 ｜ 依赖 F-69（`F-69 已提交`）、F-61（`b66a700`）
- 一句话：莫洛托夫落地后，在半径 `molotov.effectRadius` 的球内挑「实心且上方是空气」的格子，**在其上方那一格追加**火或岩浆块（85 : 15）。

## 交付物（只动 `entity/thrown/MolotovProjectile.java`）

- `#scatter(ServerLevel, BlockPos)`：球内枚举候选 + 逐格放置。
- `#landingBlock(Vec3, boolean)`：落点所在的方块位置（供 scatter 用）。
- 日志一行，**格式逐字**：`莫洛托夫 候选 {N} 火 {F} 岩浆 {M}`

## 三条铁律（写错就会被判失败）

1. **追加，不是破坏**（D-58）：只往**原本是空气**的位置写；原方块一格都不许动、不许掉任何东西。
2. **候选判据**：目标格必须**实心**（`isSolidRender`，或与 §3.7 判据 2 等价的写法）且**其上方是空气**；放置的是**上方那一格**。台阶/雪层这类非实心方块的上方**不放置**。
3. **比例 85 : 15**：火的比例由 `molotov.fireChance`（默认 85.0）决定，**岩浆块是余下的百分比**——A-01 明确只留这一个概率键，**不许**再引入 `magmaChance` 或任何第二个概率键。

## 验收（五条）

1. 平地投一颗后，半径 4 格球内**只有「实心且上方是空气」的格子**上方新增了火或岩浆块；原方块逐格 `/execute if block` 与投前一致，一个都没少。
2. 在非 `isSolidRender` 的方块（台阶 / 雪层）上方不放置任何东西（`12-TECH §3.7` 判据 2）。
3. 连投 **20 颗**，`岩浆块 / (火 + 岩浆块)` 落在 **10 %–20 %** 区间（85:15 的粗核）；日志三次数值可直接相加核对。
4. 把 `molotov.effectRadius` 改成 `1.0` 后重投，日志里的 `候选 {N}` **明显变小**（半径确实读 config）。
5. 单次投掷在同一刻内完成，服务端日志**无** `Can't keep up` 行（上限约 268 次 `setBlock`）。

## 实现提醒

- 半径 4 的球内格数约 268，这就是「上限约 268 次 setBlock」的由来；**不要**逐格 `UPDATE_ALL` 触发大范围连锁，考虑用合适的 block update flag（说明你的选择与理由）。
- 火是 `BaseFireBlock`，**会自己蔓延**。验收 3 连投 20 颗前请想清楚如何避免前一颗的火把后一颗的候选/统计污染（例如每颗之间清场，或统计只取放置瞬间的计数）。**统计口径以你日志里打出的 F/M 为准，不要靠数世界里的方块。**
- 随机源沿用仓库既有写法（看其它 impl 用的是哪一个），不要自己 new 一个 `Random`。
