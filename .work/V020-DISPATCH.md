## 3. 每个子代理统一的硬约束

1. 构建**只能**走 `.tools\gw.cmd`，禁止直接调 gradle。
2. **禁止任何 git 写操作**；只许 `git status` / `git diff` / `git log` 取证。提交由调度者做。
3. **禁止改 `docs/`**（34~39 与 00~33 全冻结）、`build.gradle`、`.tools/`、`run/`（计划外的 toml 变更除外）。
4. 每条判据**改前先跑一遍并记下实测值**（38 号陷阱 20 的元规则），改后再跑一次。
5. 渲染 / 听感类标「未验证」+ 原因；代码层证据要给文件:行号与代码片段，并注明「未经真机验证」。
6. 一个任务一组文件；回报按任务分段，方便调度者**一任务一提交**（37 §0.4）。
7. 拿不准的写进「未决问题」，不许自己定新数值、不许「先这样后面再改」。
8. 遇到做不下去的：停下，写清阻塞点与已做部分。

## 4. 调度者的复核动作（每个 Phase 后）

1. 读 `git status` / `git diff --stat`，确认改动面只落在本 Phase 任务清单内。
2. 亲自跑闸门命令（build / jar 版本行 / grep / 计数 / 起服读日志），不采信子代理自述。
3. 通过则**按任务分段提交**；不通过则带证据重派，同一任务书最多重派两次。
