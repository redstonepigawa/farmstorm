### 3.2 两个状态效果（D-81 ~ D-83）

#### D-81 · Q弹（q_bounce）

- **编号**：D-81
- **结论**：时长由施加方决定（朋友的韭 给 **10 秒 = 200 刻**）；图标用 preview.jpg → 18×18 PNG；可见图标。
效果期间：客户端把受效果生物的模型摆成**乘坐姿势**、持续旋转、反复压缩拉伸；同时**锁住全部操作**。
锁操作复用 0.0.2 的七段输入锁（D-79），不另写一套。
- **依据**：效果本体不设时长键，因为 Q弹 的时长由来源决定（D-85 给 200 刻），写死一个效果自身的键会出现「两处都能定时长」的双源；这也是 v0.0.2 D-50 那套「效果存在 + amplifier + 剩余时长即完整状态」的直接后果——时长由施加方写入，客户端只读。图标 18×18 沿用 D-53 已定的效果图标规格；素材是 1024×1024 JPG（施工事实卡 §1.3），必须转换后再进 jar。锁操作复用 D-79 的七段式，理由是第二套锁会与既有的七段判定互相覆盖（RT-19）。
- **落地位置**：`registry/FarmstormMobEffects.java`（`mob_effects` +2 之一，`q_bounce`）；`config/FarmstormConfig.java` 的 `qbounce.*` 四键（`poseMode` / `rotateDegreesPerTick` / `squashAmplitude` / `squashPeriodTicks`，施工事实卡 §3.3）；`client/` 的渲染侧姿势驱动；`client/InputLockHandler.java` 的锁入口（复用 D-79 的七段）；`assets/farmstorm/textures/mob_effect/q_bounce.png`；`17-DESIGN-0.0.3.md` 的 Q弹 节。

#### D-82 · Q弹 的坐姿两条实现分支并存，配置切换

- **编号**：D-82
- **结论**：config 键 qbounce.poseMode ∈ { render, mount }，默认 render。
- render 分支：客户端在 RenderLivingEvent 里改模型实例的 riding 标志并压低模型，**不碰实体本身**，不影响 AI 与碰撞箱；
- mount 分支：服务端给每个受效果生物挂一个隐形坐骑，姿势是原版真实的，但会改变实体关系与碰撞。
两条**都要实现**，作者在真机上比对后保留其一；不保留的那条要能靠 config 关掉而不删代码。
- **依据**：两条分支的代价不同——render 分支只改渲染层，代价是别的模组的自定义模型可能不认 riding 标志（RT-17）；mount 分支拿到的是原版真实姿势，代价是改实体关系与碰撞（RT-18）。这种取舍只能在真机上比对得出，写文档时无法判定，所以两条都实现、由配置切换，而不是先砍一条再返工。默认 render 是因为它不改实体状态，出错时的影响面只在画面。
- **落地位置**：`config/FarmstormConfig.java`（`qbounce.poseMode`，枚举 render/mount，默认 render）；`client/` 的 `RenderLivingEvent` 分支；服务端挂载隐形坐骑的分支；`18-TECH-0.0.3.md` 的两分支类设计；RT-17、RT-18。
- **补充**：《本条由 D-102 补充》——mount 分支只用原版既有实体类型承载坐骑，不新增 `entity_type`，`entity_types` 增量保持 +2；见 §3.6。

#### D-83 · 混乱（confusion）

- **编号**：D-83
- **结论**：**不显示图标**；**只对玩家有效**；只反移动输入（W↔S、A↔D），视角、跳跃、攻击、使用一律不动。
与 Q弹 同时存在时**输入锁优先**：被锁定时「反方向」没有意义，按锁处理。
- **依据**：不显示图标是因为它不是可收集的状态，且图标栏会暴露陷阱位置；只对玩家有效沿用陷分类的效果口径。只反移动输入、不动视角与攻击，是为了让「混乱」不变成「失控」——视角与攻击一旦反转就与 D-60 的锁重叠，也会让玩家无法自救。锁优先的判据是锁更强：反方向在锁定时没有可执行的落点，按锁处理不会丢信息（RT-19）。
- **落地位置**：`registry/FarmstormMobEffects.java`（`mob_effects` +2 的隐藏项，`confusion`，不注册图标）；`client/` 的 `MovementInputUpdateEvent` 分支（只改方向分量，不碰 speed 与视角）；`config/FarmstormConfig.java` 不设时长键（施工事实卡 §3.3 的「无键」行）；`17-DESIGN-0.0.3.md` 的混乱节。

**朋友的韭（friend_chives）：D-84 ~ D-85**

#### D-84 · 朋友的韭（friend_chives）没有原版对应物

- **编号**：D-84
- **结论**：因此**没有转换器配方**。获取只有一条路径：韭菜种子种在耕地上，成熟收获。
它仍进 converter_fuel 标签（可当转换器的合成材料）。
- **依据**：转换配方只服务「原版作物 ⇄ 改良作物」这对可逆映射（D-52 的标签口径、D-54 的双向同形）；没有对端就没有可逆的一对，硬造一条单向配方会让 `ConverterRecipe` 出现第二种形态。它作为农作物仍要能当转换器的合成材料，所以进 `farmstorm:converter_fuel` 标签——标签成员身份与「有自己的转换配方」是两件事。
- **落地位置**：`util/CropProfile.java`（第 20 条档案 `FRIEND_CHIVES`）；`registry/FarmstormItems.java`（`friend_chives` 与 `chive_seeds` 两个物品）；`util/FarmstormTags.java` 与 `datagen/ModItemTagsProvider.java`（`converter_fuel` 追加一项）；`datagen/ModRecipeProvider.java` 不生成它的转换配方。

#### D-85 · 朋友的韭 = 投掷型 + 增益类

- **编号**：D-85
- **结论**：投出后对落点 **欧氏 6 格**球体内的生物施加 **10 秒 Q弹**。
**若本次投掷命中了至少 1 个生物**，在落点播放一次音效，**32 格内玩家可闻**；没命中则不播。
- **依据**：球体用欧氏距离，与 v0.0.1「增益光环用欧氏半径」的口径一致（`00-DECISIONS.md` D-20）。音效只在命中时播放：空投也响会让「有没有打中」这个反馈消失，而 32 格的可闻半径是让同队队友也能听见命中的判定结果。10 秒与 200 刻是同一个值的两种写法（D-81），由本条作为施加方写死。
- **落地位置**：`entity/thrown/` 的朋友的韭投掷物（`entity_types` +2 之一）；`sound_events` +1（`friend_chives` 命中音，mono 64 kbps OGG）；`config/FarmstormConfig.java` 的 `friend_chives.hitRadius` 6.0、`effectTicks` 200、`soundRange` 32.0（施工事实卡 §3.3）；`17-DESIGN-0.0.3.md` 的朋友的韭节。

**近防菌（point_defense_fungus）：D-86 ~ D-89**

#### D-86 · 近防菌（point_defense_fungus）= 部署型 + 炮台类，对应诡异菌

- **编号**：D-86
- **结论**：转换配方：minecraft:warped_fungus ⇄ farmstorm:point_defense_fungus，双向，3 点经验，无催化剂（与 D-54 同形）。
- **依据**：对应物是诡异菌，与 D-54 的狂野苹果完全同形——双向、3 点经验、无催化剂，直接复用 `ConverterRecipe` 的常态形态，不新增配方类型。分类挂炮台类，但拦截对象由 D-87 收窄到本模组投掷物，这与 C-3 对 man瓜 的处理是同一手法：分类给玩家看，实际判定按行为走。
- **落地位置**：`datagen/ModRecipeProvider.java`（转换配方 +1，`bidirectional=true`）；`util/CropProfile.java`（第 21 条档案）；`behavior/DeployedKind.java`（枚举 +1 值 `POINT_DEFENSE_FUNGUS`）；`registry/FarmstormBlocks.java`（部署方块 `point_defense_fungus`）；`17-DESIGN-0.0.3.md` 的近防菌节。

#### D-87 · 近防菌只拦本模组的投掷物

- **编号**：D-87
- **结论**：范围：以自身为圆心 **欧氏 8 格**的球内。只拦 ThrownCropEntity 家族（0.0.2 的 9 种 + 0.0.3 新增的 2 种）。
**原版箭 / 雪球 / 三叉戟 / 末影珍珠一律不拦。**
- **依据**：判定面限定在 `entity/ThrownCropEntity.java` 这一条基类上——v0.0.2 已有 9 个 `entity_type` 走它，v0.0.3 再加 2 个（施工事实卡 §1.2、§3.1），一个 `instanceof` 就能覆盖全部，不需要逐件登记。原版投掷物一律不拦，是因为拦原版箭会改变原版战斗与其它模组的射弹手感，收益远小于风险；这一条比 C-3（man瓜 拦投掷物）更窄，属于本模组内部的自保机制。
- **落地位置**：`behavior/` 的近防菌扫描与拦截判定（按 `DeployedKind.POINT_DEFENSE_FUNGUS` 分派）；`config/FarmstormConfig.java` 的 `point_defense_fungus.interceptRadius` 8.0（施工事实卡 §3.3）；RT-20（逐 tick 扫描的代价与错峰）。
- **补充**：《本条由 D-98 补充》——拦截只对**非己方**投掷物生效（己方穿过不拦、也不扣次数），家族规模订正为 10 + 2 = 12；见 §3.6。

#### D-88 · 近防菌的拦截计数

- **结论**：触发端（非己方玩家进入）与效果端（对半径内所有玩家施加）**都用严格小于 4.0**。不许一端写「< 4」另一端写「≤ 4」，否则会出现「没触发却被施加」的自相矛盾。
- **依据**：D-92 只写「欧氏距离 < 4」与「半径 4 内所有玩家」，两端若取不同比较符，边界上就会出现「陷阱没触发、玩家却已被施加混乱」的状态。这条与 D-94 的比较符订正同一性质：**比较符是决策的一部分，不是排版**。
- **落地位置**：`behavior/` 的震动豆触发与结算（同一常量、同一比较）；`config/FarmstormConfig.java` 的 `vibration_bean.triggerRadius` 4.0 只给一个键，两端共用；`18-TECH-0.0.3.md` 的判定表；本文 D-92 末尾的补丁行。

#### D-102 · Q弹 的 mount 分支不得新增 entity_type

- **编号**：D-102
- **结论**：坐骑用**原版既有实体类型**承载，不注册新的 entity_type；entity_types 增量保持 **+2**（两个投掷物）。具体用哪个原版类型由 18-TECH-0.0.3 §4 定死。
- **依据**：D-82 只要求「两条分支都实现」，没有授权扩大注册面。挂载实体必须不可见、无碰撞、随生物死亡一起移除（RT-18），原版类型已经够用；新增一个只为姿势服务的实体类型，等于给 `entity_types` 加一条谁都不会主动使用的注册项。与 D-100 同向：两处都必须用现成的东西，不许顺手扩大注册面。
- **落地位置**：`18-TECH-0.0.3.md` §4 的实体表（写明复用的原版类型与其属性覆写）；Q弹 的 `qbounce.poseMode = mount` 分支；本文 D-82 末尾的补丁行。
