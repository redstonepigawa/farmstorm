### 0.2 术语表

本节给每个术语**判定边界**，不是同义词循环。下游五份文档遇到这些词，一律按本节的边界用。

**平凡农作物**
：本版新增的**物品类**的第一个成员 `farmstorm:plain_chives`（平凡韭菜）：只有食物属性、**没有 `CropProfile`**、不是作物、不能种、不参与任何作物机制的普通物品。判定边界：它不是「改良作物的降级版」（没有对应关系表、不进 `MODIFIED_CROPS` / `SEEDS` 标签、不参与转换）；不是「原版物品的替代品」（不喂村民、不做合成——裁定 #3）；它唯一的作用是给「没有原版对应物的改良作物」在植物学家交易里提供一个**可买到的对应物**（plan `:16` 的目的）。⚠️ 它和 `friend_chives`（朋友的韭，一个**作物**）是两个东西：后者有档案、能种、有投掷物。

**处理方块**
：带 `farmstorm:processing_block` **方块标签**的方块。本版成员**只有** `farmstorm:cultivator`。判定边界：标签在**方块侧**（`TagKey<Block>`），不是物品标签、不是 block_entity 标签；它决定的判据只有「能不能被据点核心绑定」这**一条**，不改方块的任何其它行为；「处理」是名字，不是「会处理物品」的语义——`converter` **不在**标签里，它的行为本版一行不动（裁定 #5）。

**职业方块**
：能让植物学家认领并「上班」的方块——本版定为**据点核心**（`farmstorm:outpost_core`），经 job site 与职业绑定（裁定 #8）。判定边界：职业方块**不是**「要空手右键」、**不是**「要放在核旁边」、**不是**「必须无主核」；有主核（`ownerUuid` 非空）**同样**能被认领，`ownerUuid` 与 POI **无关**；一个核只能被**一个**村民认领（裁定 #9）；「职业方块」也不是「交易发生地」——交易仍在村民身上发生。

**job site**
：原版 `PoiType` + `VillagerProfession` 机制里「哪个方块位置算这个职业的工作点」的那条注册表数据。判定边界：job site 是**方块位置**（`PoiType` 的匹配集），不是方块实体、不是菜单、不是网络包；本项目**从未**注册过 `PoiType`（`BRIEF` §1.6：全仓 `PoiType` / `VILLAGER_PROFESSION` / `POINT_OF_INTEREST` 命中均 0）⇒ 本版是第一次。**「job site」与「职业方块」是同一件事的两个说法**：前者是原版机制名，后者是玩家可见的说法，本文两个词都写、指同一个方块。

**补货**
：原版村民在工作站点旁休息后重新开张时，把报价的 `uses` 归零的那个**原版动作**（`BRIEF` §2 #18 引 `Villager#restock()`，`Villager.java:398-408`）。判定边界：补货**只** `resetUses()`——**不重新生成报价、不重抽、不改价格**；报价一经生成即写进村民 NBT。因此「每次补货重抽」在本版**做不到**（裁定 #18），本模组也**不控制**补货、不注册补货逻辑。

**断货**
：一个报价的 `uses` 达到 `maxUses` 之后进入的**不可交易**状态（`MerchantOffer` 的 `uses` / `maxUses` 计数）。判定边界：断货**不等于**补货会换内容（见上条）；断货**不等于**这个村民不再卖别的（其它报价各自计数）；数值 `maxUses` 决定的是「断货前能成交几次」，不是「一次给几个」。

**沿用 / 搁置**
：两个处置谓词，专用于「plan 的一条要求在本版落不落地」。**沿用** = 这条要求的语义本版**照旧保留、一行不改**（例：农民的 3 项交易，裁定 #7；D-176 / D-177 的补绑逻辑）。**搁置** = 这条要求**本版整条不做**，但**不是删除、不是否决**，留到 **0.2.3**（例：转换器重做的 5 项，裁定 #5）。三者界限必须分清：沿用 = 不动且有效；搁置 = 本版不做、以后做；墓碑（§6）= 不做且不打算做。**搁置不进 §3.3 的删除表、也不进 §6**。

**口径差异**
：plan 的**文字**与作者**裁定**（或与源码事实）指向不同行为的那些点。判定边界：口径差异**不是笔误、不是「plan 写错了」**——它是作者重新拍板的结果，因此**按裁定写**，同时把 plan 的原文**登记出来**（§7 ② 是一条；§7 ③ 属搁置，不属于这一类）。处理口径差异只有两个动作：**按裁定实现** + **在本文登记**；三个禁止：不许照抄 plan 的措辞当行为描述、不许把差异当 bug 修、不许改 plan 原文。

### 0.3 四字段写法

每条决策固定四项，**缺一不可**，顺序固定：

| 字段 | 写什么 | 不许写什么 |
|---|---|---|
| **结论** | 一句话、祈使句、可直接执行 | 条件句、备选句、「可以考虑」 |
| **依据** | `BRIEF` §2 的裁定编号，或 §1 / §3 / 源码的 `文件:行号`；两者都给最好 | 「因为合理」「符合直觉」「业界惯例」 |
| **落地位置** | 要改的 `路径` 或 `类#方法` | 代码片段、算法步骤 |
| **补充** | 这一条**连带会影响什么**、**否决掉了哪些替代方案** | 实现细节（那是 48 号的事）、任务排期（那是 49 号的事） |

五条写作纪律：

1. **「本文补充」标记**：凡由本文推导、而非 `BRIEF` 直接给出的口径，在该句前标 **本文补充**。带这个标记的条目可以被作者否决；不带标记的是 `BRIEF` / plan 的转写，否决它等于否决作者裁定。
2. **数字纪律**：所有数值只能追到 `BRIEF` §0 / §1 / §2 / §3 的某一条，或两个已给数值的算术（如 97 + 1 = 98、338 + 2 = 340、6 × 18 + 17 = 125、64 × 64 = 4096）。**需要新数值的**写成「由 47 / 48 号定」，本文不自己编。
3. **禁用词**：不出现未定事项与待办标记；不用第二人称敬语，一律用「作者」。
4. **与源码的关系**：本文与源码冲突时报给作者，不自行取舍，也**不改** `BRIEF`、不改任何既有文档。
5. **只写决策**：不写实现步骤、不写任务拆解、不写排期、不写验收细则——它们分别是 48 / 49 号的事；本文只给「定为 X」与「为什么是 X」。

## 7. 本版遗留（登记，不算缺陷）

以下八条是**本版有意不做 / 已知存在的**，不是漏项。下游可以引用，但不得把它们写成待办或缺陷。

1. **22 项只显示 2 项**（裁定 #17，D-198）。原版 `Villager.java:875` 写死每级抽 2 ⇒ 每个植物学家最多卖 22 项里的 2 项，玩家要多找几个才能凑齐。这是**玩家可见的已知限制**，必须出现在 47 号的设计文档与 `README.md` 里；任何「修好它」的实现都会同时违反裁定 #11 与 #17。
2. **plan 说「额外刷新出」，实际是固定 1 项**（`plan0.2.2.txt:11`；D-199）。plan 的措辞若被照抄，会被读成「每次补货换一个史诗项」；真实口径是**首次生成时抽定、之后不变**（裁定 #18）。这是**口径差异**，不是笔误，也不是本版改了需求。
3. **转换器整条留到 0.2.3**（裁定 #5）。搁置清单五项：改名、铁砧硬度、右键放入、30 秒产出、翻书动画。转换器**当前功能照旧**（配方、燃料标签、`converting` 类型、`converter` 菜单都在），本版一行未动；它属于**搁置**，不属于删除（§3.3 第 1 条）、也不属于墓碑。
4. **`MAX_LINKS` 的注释算术与容量上界不一致**（`BRIEF` §1.7；D-201）。注释写「上界 64 × 上界 16 = 1024」，但 `cultivatorCapacity` 的范围上界是 **64**（`FarmstormConfig:956`）⇒ 按「上界 × 上界」应是 64 × 64 = **4096** > `MAX_LINKS` 的 1024。本版**只改注释**（随新的默认值 24 重写），**常量不动**：实际值（默认 4 核 × 24 = 96）远小于 1024，没有人会撞上解码上限。
5. **改默认值不更新老存档的 toml**（`BRIEF` §1.8；D-202）。盘上仍是 2 和 16，升级后老存档不动 ⇒ 会收到「上限没改成 4」的误报。这是 NeoForge 的既定行为（只补键 / 删键，不改已存在键的值），不是缺陷；本版不写迁移代码。
6. **有主核也能当工作台，且一核一村民**（裁定 #8 / #9；D-196）。两个后果都是**作者接受的行为**：村民会跑到玩家基地「上班」；想多几个植物学家就得放更多核。不许加「必须无主 / 必须己方」的判据，也不许扩成「一核多村民」。
7. **`plain_chives` 没有配方，入口只有创造栏 / `/give` 与植物学家交易**（D-193）。这与 0.2.0 培养器的处置同类（没有配方时「创造栏 + `/give`」是仅有的入口）：玩家若找不到植物学家就拿不到它。这是裁定 #2 / #3 的必然结果，不是漏做配方。
8. **「名额共享」在本版没有可观测差异**（裁定 #15；D-194 / D-195）。标签目前只有 `cultivator` 一个成员 ⇒ 「所有带标签的方块共享 24」与「培养器 24」在**数值表现上完全等价**。本版定的是**判据**（按标签），不是行为差异；将来第二个成员被加进标签时，共享语义立刻生效，无需再改容量键。
