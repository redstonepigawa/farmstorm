## 0. 你面对的是什么

v0.2.2 是**小增量**：`plan0.2.2.txt` 的 5 条需求拆成 **19 个任务**（F-267 ~ F-285）、**8 个 Phase**（46 ~ 53），注册面 **+1**、config **键 +0**、语言键 **+2**。它不像 0.2.0 那样整块换机制，**但有三处不是「照着抄一个类」能过的**——三处都不是工程量的问题，是「读错一句就整版白做」的问题。

|---|---|---|---|---|
| 1 | **两个「缺一行就复现」的 bug** | tooltip 缺一次 `renderTooltip` 调用；背包错位是**单次 blit vs 两次 blit**（原版下段把贴图 `v=126` 画到 `y=125`） | 0.2.1 判过「默认链路本就该显示」，为此**只加验收、没改代码**（F-251）——判断错了（D-192）。这两个 bug 在源码里都「看起来是对的」，只有开界面能证伪 | R4；48 §2.1 / §2.2；F-270、F-271 |

**四条最贵的读法**（背下来，它们决定了本版一半的返工）：

1. **22 个 listing ≠ 22 项可见**：22 项全进 1 级，但原版每级只从该级列表里抽 **2** 条（`Villager.java:875`）⇒ **每个植物学家只显示 2 项**，满级共 3 项。这是**作者接受的已知限制**（裁定 #17、D-198），不是 bug，**不许修**。
2. **改了 `defineInRange` ≠ 玩家看到 4 / 24**：老存档的 `run/config/farmstorm-server.toml` 不会跟着变（盘上 `:753` 仍是 2、`:765` 仍是 16）⇒ 「上限 4 / 绑定 24」只对**新装**生效，验收必须用**新生成**的 config。
3. **注册了 POI ≠ 村民会认领**：还必须把 `farmstorm:botanist` 加进原版标签 `minecraft:acquirable_job_site`；不加的表现是「村民四处走、永不认领」，**无任何报错**（48 §2.3.5）。
4. **98 里没有 POI 与职业**：两张新表是**口径外第 2、3 类**，不计入 98；按「新增 5 个类」推注册面会得出 103 或 99 的错误结论（48 §1.2）。

**五条需求里只有 R2 落一个物品在注册面上**：tooltip 与 blit 改在既有 `OutpostCoreScreen`；标签是 datagen；两个数值是 config 默认值；职业与 POI 是口径外。⇒ **98 = 97 + 1**（只加 `plain_chives` 一个物品），`data_components` 仍 **1**、网络包仍 **2**、Mixin 仍 **0**。四个「加了但不进注册面」的构件逐个点名：`datagen/ModPoiTypeTagsProvider`、`event/BotanistTrade`、`event/BotanistEpicTrade`、`util/FarmstormTags.PROCESSING_BLOCK`——别按「新增类数」推断注册面。

## 5. 事实与推断的分界线

**必须查源码的**（查不到就不许写进代码、注释或回报的断言）：

| 类别 | 查哪里 | 查不到时 |
|---|---|---|
| 任何 `文件:行号` | 当场用 `Select-String` / 读文件确认那一行**现在**是什么（UTF-8 读法） | 不许凭 46 / 48 的引用来写注释——行号会漂移（48 §10 #8 已登记过 `block_entities` 的行号偏差） |
| API 签名与运行期行为 | `.scratch/p25a/src/`（原版 + NeoForge 两棵树）；48 §9 的 **10 条**逐条有「已核到什么程度 + 退路」 | 先写最小用例跑通，再动主线；POI 自动登记若为假，**没有**便宜退路 ⇒ 报作者 |
| 现状计数 | 自己数：`run/config/farmstorm-server.toml`、两份 `lang/*.json`、`src/main/java` 的 Java 文件数、`textures/item/` 的 PNG 数、`FarmstormTags` 的 `TagKey` 数 | 不许从 `BRIEF` / 48 §1 抄一个数当「现在的值」 |
