## 1. A-60 的完整口径（原样写进文档，不要改写措辞）

```text
核被毁时，本核名下的每一块绑定耕地只按两级处理：
  ① 找到接替核（覆盖 + 与耕地主同盟 + 有空位，最近优先 + 三级比较键）⇒ 改绑；
  ② 找不到 ⇒ 若方块仍是 minecraft:farmland 则 setBlock(DIRT) + 摘绑定；若早已不是耕地则只摘账。
不再有「因该区块未加载而只摘绑定」这一级。
```

**为什么**（这是回灌时要写进去的理由）：

- 核的 `CoreChunkTickets` 用 `addRegionTicket(..., distance = 1, ...)` 把**中心区块 + 紧邻一圈 = 3×3 区块**摁在内存里（中心 32 = ticking 档，邻圈 33 = FULL 只加载不 tick）。
- 而耕地的归属范围 `OutpostCoreBlockEntity.inRange` 恰好是**同一个 3×3 区块**（`RANGE_CHUNKS = 1`，切比雪夫）。绑定只可能落在范围内 ⇒ **「核名下的田」永远位于因票而在内存的区块里** ⇒ `getChunkNow` 恒非 `null` ⇒ 「未加载」那支进不去。
- 迁移期间票还活着：`release()`（含票释放）在 `settleOnRemoval()` 的**最后一行**才调用，在 `rebind` / `toDirt` / `unbindOnly` 全部处理完之后。
- 函数开头还有一道更粗的闸：核**自己所在**区块 `getChunkNow == null` ⇒ 直接 `return`（什么都不做）。所以「未加载」这件事在更粗的粒度上已被吸收。

**「只摘绑定」这条路径保留但不删**：它是「票没拿到 / 索引有条目但票丢了」这类异常下的兜底；日志串 `迁移失败且区块未加载：只摘绑定` 存在于 `blockentity/OutpostCoreBlockEntity.java:374`，**正常运行不出现**。

**作者本意（要写进已知限制/验收口径）**：**远端拆核也会铲田**——玩家不在场时拆核，本核名下的耕地照样变泥土。这与 v0.1.0 的「拆核铲田」手感一致，不是回归。
