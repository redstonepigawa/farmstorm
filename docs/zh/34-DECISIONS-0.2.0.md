### 0.2 术语表

本节给每个术语**判定边界**，不是同义词循环。下游五份文档遇到这些词，一律按本节的边界用。

**品质（`CropTier`）**
：作物档案上的一个**静态属性**，取值只有三档：`COMMON`（普通）/ `RARE`（稀有）/ `EPIC`（史诗）。判定边界：品质属于**档案 / 物品 id**，不属于物品实例——同一个 id 的任何一摞、任何 NBT 状态都是同一档，不随玩家、维度、时间变化；它**不是**数据组件、**不**随物品堆同步、**不**进 `BuiltInRegistries`。品质与「堆叠档」（`CropProfile.THROWABLE_STACK_TIER = 16` / `OTHER_STACK_TIER = 64`）**无关**，也不由 `CropType` / `CropCategory` 推导（D-149、D-150）。

**培养器**
：等于 **`farmstorm:cultivator`（农作物培养器）** 这一个方块及其方块实体。判定边界：「培养器」在本文件里**从不**指培养动作、不指界面（它没有界面，D-160）、不指核心、不指转换器。说「这个培养器」时指世界里那一格方块；说「这个培养器的内容物」时指它内部那一个待培养物（一次只能放一个，D-162）。

**绑定（培养器 ↔ 核）**
：一个培养器与**唯一一个**己方核之间的持久关系。判定边界：绑定是**一对一**，单位是「个培养器」；一个核最多绑 **16 个**培养器（`outpost_core.cultivatorCapacity`），一个培养器同一时刻只有 **0 个或 1 个**核。绑定的**唯一真相在核侧**（核的 16 条列表），培养器 BE 里那一份「我绑给谁」是引用缓存，使用前必须用核侧列表校验（D-165）。未绑定的培养器仍然存在、仍然能看见，只是**不可使用**。绑定**不是**「范围内的自动归属」——它不会随距离变化漂移。

**存储空间**
：据点核心那 **54 格**容器（双箱）。判定边界：它**不是**「容量 16」——16 是**培养器名额**，54 是**格子数**，两者不同义、不可互换（裁定 #8、RT-44）。存储空间是**一般容器**（玩家手动放、培养器自动投递），**不是**培养器的输入槽（培养器没有槽位界面）、**不是**玩家背包、**不是**掉落物。核心被破坏时这里面的物品**掉落**（D-167）。

**连线**
：客户端**画在屏幕上的一条线框**，表示「这个培养器绑着这个核」。判定边界：它是**纯视觉**——无实体、无碰撞、不阻挡、不发光、不产生粒子、不占注册面；任何服务端逻辑（绑定、产出、迁移、保护）**都不得**依赖连线是否存在，也**不得**依赖客户端是否收到了连线包。线框只在「玩家身处该核的 3×3 区块范围内」时下发（D-169）。它不是方块、不是实体、不是粒子。

**撤销耕地**
：本版的「撤销」= **只注释调用点**——把耕地体系的**入口**（2 个事件监听器的注册与实现、1 行启动补建调用、耕地 config 的读取与定义、3 条语言键）注释掉，使这套规则在运行期**不再生效**。判定边界：**不是删代码**（`FarmlandLedger` 555 行与 `FarmlandGuard` 225 行的类本体一行不改、仍编译、仍在源码树里）；**不是删存档**（`farmstorm_farmland.dat` 不读不写不删，D-154）；**不是删方块**（15 个作物方块照旧注册，D-155）。凡写成「删除耕地代码」「清除耕地数据」的表述都是错的（裁定 #3、RT-42）。

**断货**
：一个交易项成交一次后、在**原版补货**到达之前**不可再次成交**的状态。判定边界：断货的是**这一项**，不是这个村民、不是所有村民、不是这一档作物；交易项**仍然显示在列表里**（看得见、点得动、成交被拒），**不消失、不换 id、不隐藏**；补货到达后自动恢复（`maxUses = 1` + 原版补货机制）。断货 ≠ 移除 ≠ 「限购一次后永久消失」（裁定 #7、D-158）。

**己方**
：等于**核主本人 + 同队队友**，判定走 **UUID / 名字**、**不看目标是否在线**——沿用 28 号 **D-138**，本文不改它。判定边界：本版用到它的三处（培养器绑定选核、连线下发、核心存储的访问判定）**共用同一套**；生物恒按「非己方」处理（生物没有队伍归属）。

**迁移**
：核被拆时，把它绑定的培养器**改绑**到另一个核。判定边界：迁移的是**绑定关系**，不是方块、不是物品、不是存档；一条都迁不动时**留在原地并标记未绑定**（不消失、不变泥土、不掉落），这是与 0.1.1 耕地迁移最大的差别（D-168）。

**工作态**
：培养器**正在产出**的状态 = 「槽内有培养物」且「没有因核心满而暂停」。判定边界：空槽不是工作态；因满而暂停也不是工作态；只有工作态播放翻书动画，其余一律显示静态首帧（裁定 #12、D-161、D-164）。

### 0.3 四字段写法

每条决策固定四项，**缺一不可**，顺序固定：

| 字段 | 写什么 | 不许写什么 |
|---|---|---|
| **结论** | 一句话、祈使句、可直接执行 | 条件句、备选句、「可以考虑」 |
| **依据** | `BRIEF` §2 的裁定编号，或 §1 / 源码的 `文件:行号`；两者都给最好 | 「因为合理」「符合直觉」「业界惯例」 |
| **落地位置** | 要改的 `路径` 或 `类#方法` | 代码片段、算法步骤 |
| **补充** | 这一条**连带会影响什么**、**否决掉了哪些替代方案** | 实现细节（那是 36 号的事）、任务排期（那是 37 号的事） |

四条写作纪律：

1. **「本文补充」标记**：凡由本文推导、而非 `BRIEF` 直接给出的口径，在该句前标 **本文补充**。带这个标记的条目可以被作者否决；不带标记的是 `BRIEF` / plan 的转写，否决它等于否决作者裁定。
2. **数字纪律**：本文所有数值只能追到 `BRIEF` §1 / §2 / §3 的某一条，或两个已给数值的算术（如 19 − 8 = 11、93 + 4 = 97）。**需要新数值的**写成「由 35 / 36 号在本条框架内定」，本文不自己编。
3. **禁用词**：不出现未定事项、待办标记、条件含糊的结论；不用第二人称敬语，一律用「作者」。
4. **与源码的关系**：本文与源码冲突时报给作者，不自行取舍。写作期发现的冲突逐条列在 §9，**不改 `BRIEF`**。

- **编号**：D-164

- **依据**：裁定 #13；`BRIEF` §3.3 第 11 行（核心 54 格）；`plan0.2.0.txt:21`（「自动存放在其绑定的据点核心的存储空间中」）。

### 1.5 核心与迁移（D-165 ~ D-168）

#### D-165 · 培养器绑定：放置时绑最近的己方核，容量 16

- **编号**：D-165
- **结论**：培养器**放置时**自动绑给「**覆盖它 + 己方 + 还有空位**」的核中**最近**的一个；距离口径取 `BlockPos#distSqr`（三维欧氏平方），平手按 `placedGameTime` 升序、再按核坐标字典序；一个核最多绑 **16 个**（`outpost_core.cultivatorCapacity`，默认 16）。
- **依据**：裁定 #8、#9；`plan0.2.0.txt:26-27`；`BRIEF` §2 表下注（平手比较键沿用 0.1.1、**不需要**维度级——培养器与核必同维度）；`BRIEF` §3.4（`cultivatorCapacity` 默认 16、`storageSlots` 默认 54）；0.1.1 的距离与比较键先例 `FarmlandGuard.java:164`、`:179-189`；范围判据 `OutpostCoreBlockEntity.inRange`（`:146-157`，`RANGE_CHUNKS = 1` 在 `:53`）；每玩家 2 核上限不变（`FarmstormConfig.java:915`）。
- **落地位置**：`blockentity/CultivatorBlockEntity.java`（放置时选核 + 持久化绑定）；`blockentity/OutpostCoreBlockEntity.java`（16 条绑定列表 + 空位判定）；`config/FarmstormConfig.java:227`（字段）、`:909-912`（定义，`farmlandBonus` 让位给 `cultivatorCapacity`）。
- **补充**：**绑定的唯一真相在核侧**（16 条列表既是容量载体也是检索面）；培养器 BE 里那份「我绑给谁」是**引用缓存**，每次使用前用核侧列表校验，两侧不一致按**未绑定**处理（否则会出现「核说没绑、培养器说绑了」的双源，§9 ⑫）。**没有可绑的核时**：方块照样放下，但处于未绑定态、不可使用（plan 的「当且仅当…被绑定时可使用」）；绑定的写入**只有两个时点**——放置时、以及绑定的核被拆时（D-168）。运行期不做「就近漂移 / 定期重绑」，因此不存在第二种绑定真相。**放置时没绑上的后果**：因为绑定的写入只有这两个时点，一个放置时没有可用己方核的培养器会**永久处于未绑定**（不可使用），**除非拆掉重放**——这是刻意的，不要在运行期偷偷补绑（补绑会让「我放的时候有没有核」这件事失去意义）。`cultivatorCapacity` **不是**存储格子数（54 才是，裁定 #8；§7 第 3 条）。否决「放置后手动选择绑定核」：plan 没有选择界面，培养器无 GUI（D-160）。
